# Briefing: remove all LLM pricing data (2026-09-30)

Shared context for the agents executing this. Everything under "Settled" is
VERIFIED — do not re-derive it.

## The decision (from the product owner)

> "AI billing (llm) is supposed to be passthrough ... litellm returns the cost in
> its api response, and we should be using that." / "remove pricing from
> models.yaml as well, we actually don't display pricing anywhere anyways" /
> agreed: delete the generated pricing seeds + the unused Reserve/Finalize
> path, with a forward-only migration.

The system must hold **no per-token price table anywhere**. The only source of
an LLM cost is what the upstream reports for that request.

## Settled

1. **Billing path (control-plane).** `internal/llmproxy/billing.go` debits the
   wallet with LiteLLM's reported cost, resolved in order:
   `x-litellm-response-cost` → `x-litellm-response-cost-original` (only if > 0)
   → `usage.cost` in the body → nothing (loud log). This is ALREADY DONE and
   uncommitted in the control-plane working tree (with
   `internal/llmproxy/passthrough_cost_test.go`). `deploy/litellm/config.yaml`
   already has `litellm_settings.include_cost_in_streaming_usage: true`. Do not
   rework either.
2. **Verified LiteLLM 1.83.10 response shapes** (captured live today):
   - non-stream `/v1/chat/completions`: header `x-litellm-response-cost: 7.9e-05`.
   - non-stream `/v1/messages`: NO `x-litellm-response-cost`; only
     `x-litellm-response-cost-original: 7.9e-05`.
   - streams (both routes), with the flag on: final usage event carries
     `"usage": {..., "cost": 7.9e-05}` (chat: the last `chat.completion.chunk`
     with `usage`; messages: `message_delta`).
3. **`ReserveManagedReliantUsage` / `FinalizeManagedReliantUsage`** (control-plane
   `proto/services/billing_gateway/v1/billing_gateway.proto:29,32`,
   `internal/billing/svcbilling/handler.go:408,427`, `service.go:1972,2059`) are
   the ONLY consumers of the pricing seeds. Nothing in `reliant` calls them.
   `pricing_seeds_catalog.go` is generated by `internal/llmgateway/render.go`
   (`renderPricingSeeds`, `provisionalPricing`, `billingProvider`) from
   `llmcatalog.Model.Cost`. `directProviderPricingSnapshotSeeds` is hand-written
   in `service.go:167-180`.
4. **`controlplane.pricing_snapshots`** (migration 00038) is referenced by a
   `pricing_snapshot_id TEXT NOT NULL REFERENCES ... ON DELETE RESTRICT` column
   on TWO tables in 00038 (lines 54 and 106 — reservations and usage events).
   Other Go readers: `internal/billing/pricing/`, `svcbilling/canonical_metering.go`,
   `canonical_funding.go`, `repo.go`, `internal/db/{postgres,models,interfaces}.go`,
   `internal/billing/{funding,metering,provideradapters,inframeter}/`,
   fixtures `db/fixtures/usage_events.json`, `db/seeds/0008_usage_events.sql`.
   Some of these (inframeter, funding) may serve NON-LLM billing (compute) —
   establish that before deleting anything there.
5. **reliant consumers of `models.yaml` `cost`:**
   - `internal/llm/models/types.go` — `ModelCost` type (≈485-533), `Cost` field on
     `ModelDefinition` (266), mapping into `Model` (320-322).
   - `internal/llm/models/model.go:55-58` — `CostPer1MIn/Out/InCached/OutCached`.
   - `internal/llm/models/available_models.go:45` — `Cost ModelCost`.
   - `internal/llm/drivers/openai/driver.go:575,579-586,873,1049` — `calculateCost`.
   - `internal/llm/drivers/reliant/driver.go:857-867` — computes `TokenUsage.Cost`.
   - `internal/grpc/services/catalog.go:125-126,327-328,372-373` — fills
     `cost_per_1m_in/out` on two catalog messages
     (`proto/reliant/v1/catalog.proto:45-48` fields 7,8 and `:119-122` fields 8,9).
   - `web/src/api/client.ts:87-88,220-221` — maps them; nothing renders them.
   - `pkg/llmcatalog/catalog.go` — `Cost` type + nanos helpers + `Model.Cost`;
     `catalog_test.go` asserts them.
   - `docs/settings/model-config.mdx:154,188,216,322` — documents `cost:` for
     custom models.
   - 56 `cost:` blocks in `internal/llm/models/definitions/models.yaml`, plus the

   - Tests: `internal/llm/models/sept_2026_models_test.go` and

6. **Per-call cost in reliant** (`llm.TokenUsage.Cost` → `call_llm.go:2715`
   `state.cost` → `save_message.go:757` → hidden `messages.cost` column;
   `CallLLMOutput.cost` proto field 9 is documented "Request cost in USD when
   returned by the provider response"). Nothing reads it for display. Keep the
   plumbing; only its SOURCE changes: it must be a provider-reported cost, never
   catalog math. The reliant (gateway) driver should read LiteLLM's reported
   cost per fact 2; every other driver leaves `Cost` 0.
