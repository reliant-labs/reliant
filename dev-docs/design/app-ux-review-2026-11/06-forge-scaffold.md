## 2. Measured baseline

**Type scale in use:**

- 10px: avatar initials.
- 12px: section labels, captions, badges.
- 14px: body, table, controls.
- 20px/600: every page h1.
- 30px/600: tile numbers.
- 30px/700: the h1 on 404 and error pages.

That is a coherent shadcn-like scale except for the 404/error h1.

**Font:** the declared face is Inter, but it **never renders** (F1). Body text falls back to the OS stack (`-apple-system, "Segoe UI", Roboto, …`).

**Palette:** fully tokenised oklch neutrals at hue 262, with chroma ≤ 0.012. The accent is `oklch(53% 0.17 258)` in light mode (≈ `#2068cc`) and `oklch(71% 0.14 256)` in dark mode. The palette is neutral and restrained, which is the right stance.

**Elevation:**

- Light mode: `main` is `surface-muted` (`#f6f7f9`) and cards are `surface` (`#fdfdff`). The two differ by about 1.03:1, so cards are separated only by their 1px border, which is a Vercel-like treatment.
- Dark mode: 16% L shell, 20% L content column.

**Contrast (light mode):** every body and table text passes (6.2–17.5:1). The failures are:

| Text | Ratio | Where |
|---|---|---|
| `ink-subtle` on `surface` | 3.90:1 | "NAVIGATION" label, "Total customers" captions |
| `ink-subtle` on `surface-muted` | 3.69:1 | "QUICK ACTIONS" |
| Avatar initials | 2.89:1 | white on `bg-orange-500`, 10px |

**Contrast (dark mode):** only the avatar fails.

**Radii in use:** 4px (theme segments), 6px (nav, filters, picker, Edit/Delete, pager), 10px (list "Create" link, create/edit text inputs, dialog buttons, tiles).

**Control heights:** 28 (header), 32 (detail actions), 34 (pager), 36 (Create, selects), 38 (inputs), 40 (FK picker, sign-in submit). These measured outcomes come from root cause R1 below.

**Root cause R1, which drives most consistency findings:** the generated pages don't use the component library they install. Of the 35 components auto-installed into `src/components/ui/`, 25 are imported by nothing:

- `input`, `label`, `form`, `select`
- `card`, `table`, `data_table`, `filter_bar`
- `empty_state`, `confirmation_dialog`, `pagination`, `search_input`
- `tabs`, `chip`, `tag`, `status`, `stat_grid`, `metric_card`, `row_actions_menu`
- `login_form`, `sidebar_layout`, `link`, `mono`, `progress_bar`, `button_classes`

The pages hand-roll their own class strings instead (`pages/*.tmpl`, `web-runtime/src/resource.tsx`). So the same control is styled in three places that have already drifted apart. A user who restyles `ui/button.tsx` or `ui/input.tsx` changes nothing on their CRUD pages.

## 3. Findings, by surface

Severity: **B** = broken/bug, **A** = accessibility, **C** = craft/consistency, **K** = copy.

### Root layout, fonts, theming

- **F1 [B] Inter is declared but never applied.** Forge bug a5c734da.
  - `layout.tsx.tmpl:136` puts `${inter.variable}` on `<body>`.
  - `globals.css:89` declares `--font-sans: var(--font-inter), …` inside `@theme`, and Tailwind v4 emits that on `:root,:host`.
  - At `:root`, `--font-inter` is undefined, so `--font-sans` is invalid at computed-value time and `font-sans` falls through to the system stack.
  - Measured: `getComputedStyle(:root).--font-sans` is `""`, every Inter `FontFace` is `unloaded`, and the body font is `-apple-system…`.
  - Effect: every forge app, and every "Forge app" screenshot, renders in whatever the host OS has, despite the long comment explaining that Inter is the deliberate neutral default.
- **F2 [B] The mock-mode banner never renders in a static export.** Forge bug a756ea18.
  - `MockModeBanner` is in the server `RootLayout` (`layout.tsx.tmpl`). At build time `window` is undefined, so `config_gen.ts` reads `process.env.MOCK_API` (unset) and the banner is compiled out. `grep -c "MOCK DATA" out/index.html` returns 0.
  - The transport (`connect.ts`) decides mock mode client-side from `config.js`, so the preview serves fixtures with no banner. This is exactly the masquerade the frontend skill says the banner exists to prevent.
  - The Vite SPA renders its banner client-side (`vite-spa/src/App.tsx.tmpl`), so it does not have this bug.
- **F3 [A] No `color-scheme` is declared.** `globals.css` (light block at L~100, dark blocks at L136 and L170) never sets `color-scheme`, so the computed `colorScheme` is `normal` in dark mode. Native `<select>` popups (every list filter and enum select), the `datetime-local` picker and scrollbars all render light-on-dark.
- **F4 [A] `ink-subtle` is used for 12px text at 3.69–3.9:1** (light mode). `globals.css:108` comments it as "tertiary / placeholder / icons", but it is used for text in:
  - `nav.tsx.tmpl:155` (the "Navigation" label);
  - `dashboard.tsx.tmpl`: tile captions and the "Quick actions" h2 (L78).
- **F5 [A/C] The avatar uses a raw palette.** `pkg/components/components/ui/avatar.tsx:47-54` hashes names onto `bg-{blue,green,purple,pink,indigo,teal,orange,cyan}-500`. It is the only raw palette class in the app, which the frontend skill itself calls a forge bug, and the white initials measure 2.89:1. Forge bug b0bbecea.
- **F6 [K] Every route has the same document title, `web | fieldops`.** `layout.tsx.tmpl:25` builds `"{{.FrontendName}} | {{.ProjectName}}"`, which leaks the frontend's directory name into the tab title. Pages export no per-route `metadata` or `document.title`, and the description is "Frontend for the fieldops project".

### App shell: sidebar, header, user menu

- **S1 [K/C] A lone "NAVIGATION" group label.** `nav.tsx.tmpl:152-156` labels the only group in the sidebar. A single unlabelled list (shadcn sidebar-01, the Vercel dashboard) is cleaner. A label earns its place only when there are several groups.
- **S2 [A] The sidebar `<nav>` has no `aria-label`, and there is no skip link.**
  - The detail page also renders a "Breadcrumb" `nav`, so the main nav is the one unlabelled landmark.
  - `app_shell.tsx.tmpl` has no "Skip to content" link, and `main` has no `id`. A keyboard user tabs through 5 nav and header stops before reaching content (measured tab order: Open navigation, Light, Dark, System, user menu, filters…).
- **S3 [A] The theme toggle is three tab stops.** `theme-toggle.tsx.tmpl:37-60` is a `role="radiogroup"` whose radios are each in the tab order. The ARIA pattern is a single roving stop with arrow keys.
- **S4 [A] The user menu has no menu semantics.**
  - `session_nav.tsx.tmpl`: the trigger has `aria-expanded` but no `aria-haspopup` or `aria-controls`.
  - The panel has no role, and focus does not move into it on open. Clicking the trigger leaves `activeElement` on `BODY`.
  - "Sign out" has no `focus-visible` style.
  - Escape does close the menu and refocus the trigger (good).
- **S5 [A] Touch targets are below the design skill's own 44px floor** on mobile: theme segments 28×28 and the user button 96×28 (`theme-toggle.tsx.tmpl`, `session_nav.tsx.tmpl` via `Button size="sm"`). The design skill sets the floor ("Touch targets: ≥ 44px square") and the scaffold misses it at 390px.
- **S6 [A] The mobile drawer works, with one gap.**
  - It is `role="dialog"`, `aria-modal`, and labelled "Navigation". Focus goes to Close on open and Escape closes it.
  - After closing, focus was on `BODY` rather than the "Open navigation" trigger. This was measured with a synthetic Escape event; verify with a real key.
  - Source: `nextjs/src/components/mobile_nav.tsx.tmpl`.

### Dashboard (`/`)

- **D1 [K] Placeholder copy is shipped as if it were final.**
  - "Overview of your application resources." (`nextjs/src/app/page.tsx.tmpl:15`).
  - "Total customers" under a tile already titled "Customers", so the noun is said twice.
  - "QUICK ACTIONS" duplicates the per-list "Create" buttons, and words them differently: the dashboard says "New Job" while the list, form title and submit button say "Create Job".
- **D2 [C] The page is thin for a first impression.**
  - Three count tiles and three outline buttons fill about 300px of a 1905px-wide, 900px-tall viewport (`dashboard.tsx.tmpl`). There is no recent-records surface, even though every entity has `updated_at` and a list hook.
  - For the screenshots we put on the landing page, this is the weakest screen.
  - Tiles are well built: live `totalCount` (not the page length), `tabular-nums`, a hover-only chevron, and a `focus-visible` ring.

### Generated list pages (`/jobs`, `/customers`, `/technicians`)

- **L1 [B] Foreign keys render as raw UUIDs under "Customer Id" / "Technician Id".** Forge bug 28d28465.
  - `internal/codegen/frontend_pages.go:1760-1766` appends a copy of each column to `ListColumns`.
  - `internal/codegen/frontend_pages_fk.go:182-187` (`AttachForeignKeys`) sets the FK and trims the label only on `page.Columns`. That is why the **detail** page correctly shows "Customer: sample_name_1".
  - `pages/list-page.tsx.tmpl:94-110` also has no FK cell branch.
  - The 36-character UUIDs wrap and make rows 61px tall at 1905px.
- **L2 [C] FK filters are free-text UUID inputs.** `list-page.tsx.tmpl:276,294` renders `<input type=search placeholder="Customer Id">` for `customer_id` / `technician_id`. Nobody types a UUID. An `EntityPicker` (already scaffolded) is the right control.
- **L3 [B, mobile] The list header overflows at 390px.**
  - On `/jobs`, the header's action row is 865px wide inside a 342px header, the "Create Job" button sits at x=793 (off-canvas), and `main` scrolls horizontally (`scrollWidth` 889 vs 390). `/customers`, with one action, fits.
  - Cause: `web-runtime/src/resource.tsx:103-110` puts title, count, every filter and the CTA in one `flex justify-between` row with no wrap. `list-page.tsx.tmpl` passes all filters through `actions`.
- **L4 [C] The filter UI is split.** The search box sits under the header (`resource.tsx:116-124`, `max-w-sm`), the enum and FK filters sit in the header row, and "10 total" sits between the title and the filters. `ui/filter_bar.tsx` (auto-installed for exactly this) is unused. The usual pattern (shadcn tasks example, Vercel) is one toolbar row under the title (search, then facets, then a reset), with the count in the pager.
- **L5 [C] No sorting.** `ListJobsRequest` carries `order_by` and `descending`, but `<Resource>` has no sortable headers and no `aria-sort` (`resource.tsx:129-142`). The API capability is unreachable from the UI.
- **L6 [A] Rows are `<tr role="button" tabindex=0>`** (`resource.tsx:166`). This overrides row semantics, so a screen reader announces a button rather than a table row, which defeats the sr-only caption the component carefully adds. There is also no visible link affordance. The standard is a real `<a>` in the primary cell, optionally with the row click as a pointer convenience.
- **L7 [C] The pager is just Previous / Next** (`resource.tsx:200-218`). There is no "1–10 of 10" and no page size. Both buttons show even when disabled on a single page.
- **L8 [K] Header labels leak column names.**
  - "Estimate Cents" heads a column formatted as money (`$0.01`). `fieldNameToLabel` (`frontend_pages.go:461`) does not drop the `_cents` suffix that `isMoneyColumn` (L1829) already recognises.
  - "Scheduled At" reads better as "Scheduled".
- **L9 [K] One empty state for two situations.** "No jobs found / No records match the current view." (`list-page.tsx.tmpl:247` and `resource.tsx:155-157`) is shown both for a truly empty table and for a filtered-to-zero view. The first wants a "Create the first job" CTA; the second wants "Clear filters".
- What works well: URL-backed filters (`useTypedSearchParams`), enum filters that drop `UNSPECIFIED`, `keepPreviousData`, a loading skeleton with `motion-reduce`, and an error state with retry and `userMessage()`.

### Detail page (`/jobs/view?id=`)

- **V1 [C] Key/value rows are `flex justify-between`, zebra-striped, with the value right-aligned** (`pkg/components/components/ui/key_value_list.tsx:53`). Long values (description, notes) right-align against a far edge at 1216px. A two-column `dl` grid with left-aligned values (shadcn's "description list") reads better.
- **V2 [K] The record title appears three times:** breadcrumb leaf, h1, and the first "Title" row. `pages/detail-page.tsx.tmpl` could drop the row of the field used as the h1.
- **V3 [K] The delete dialog doesn't name the record.** "Are you sure you want to delete this job?" (`detail-page.tsx.tmpl:175`; `vite-spa-pages/detail-page.tsx.tmpl:136`). It should say "Delete "sample_title_1"? This can't be undone." The dialog itself is good: `aria-modal`, labelled and described, initial focus on Cancel, and Delete uses the danger token.
- **V4 [C] No feedback after delete.** On confirm, the page navigates to the list with no toast (measured: the toast region stayed empty). Create and edit land on the record, which is acceptable, but delete is the case that needs "Job deleted".
- Not-found works: "job does-not-exist not found" plus "Back to jobs", inside a danger alert. The copy is the raw server message. A designed state ("This job doesn't exist or was deleted") would read better.

### Create / edit forms

- **E1 [A] Errors are not wired to their inputs.** In `pages/_partials.tmpl`, `create-page.tsx.tmpl:152` and `edit-page.tsx.tmpl:244…292`:
  - inputs get no `aria-invalid` and no `aria-describedby` pointing at the `<p>` error (measured: both null after a failed submit);
  - required is shown only as a literal `" *"` in the label text, with no `aria-required` (`_partials.tmpl:16`).
  - Focus does move to the first invalid field (good).
- **E2 [K] Raw zod messages.** The projected `min_len 1` rule emits `.min(1)` with no message, so the user reads **"String must contain at least 1 character(s)"**. `attachZodExpr` (`frontend_pages.go:~1414`) skips its own `"Required"` when the projected chain already has `.min(N)`. The FK field next to it says "Required", so one form uses two voices.
- **E3 [B] Seeded and mock emails fail the generated validator.** Forge bug 2a8070c7.
  - Fixtures hold `1@1.1 … 10@10.10`. These pass the born CHECK `^[^@\s]+@[^@\s]+\.[^@\s]+$`, but fail `z.string().email()`.
  - Result: on every seeded customer, Edit, change Phone, Save gives "Invalid email" under the untouched Email field.
- **E4 [C] Money is entered as cents.** "Estimate Cents" is a text input validated by `/^(-?\d+)?$/` ("expected a whole number"), so the user types `1500` for $15. The runtime already ships `parseMinorUnits` / `formatMinorUnits` / `minorUnitsToInput` for exactly this, and the frontend skill documents them.
- **E5 [C] Inconsistent controls in one form.** Text inputs are `rounded-lg` (10px) and 38px tall, the FK picker is `rounded-md` (6px) and 40px, and the selects are 36px. Description and notes are single-line `<input>`s. This is the measured outcome of R1.
- **E6 [A] The FK picker loses focus after a keyboard pick.** `shared-web/src/components/entity-picker.tsx.tmpl` gets a lot right: `aria-haspopup=listbox`, the search box takes focus on open, `aria-activedescendant`, and ArrowDown+Enter commits (verified with real keys). But after the commit, `activeElement` is `BODY`, not the trigger, so the next Tab starts from the top of the document. `commit()` (L205-211) should refocus the trigger.
- Enum handling is correct: no `UNSPECIFIED` option, the required enum defaults to the first member (the column DEFAULT), and the optional enum offers "None". Edit's Save is disabled until the form is dirty, and Cancel returns to the record.

### Auth

- **A1 [B] An expired session is never handled.** Forge bug 330ac82a.
  - `src/lib/events.ts:29` declares `auth:expired`, but nothing emits or subscribes to it.
  - `query-client.ts` only toasts, and `RouteGuard` (`shared-web/src/lib/auth/route-guard.tsx.tmpl`) trusts the initial session fetch.
  - So a session that lapses mid-use leaves every list on an error panel and every mutation on a toast, never on `/auth/sign-in?returnTo=…`.
- **A2 [A] Sign-in inputs show focus by a 1px border-colour change only.** `nextjs/src/app/auth/sign-in/page.tsx.tmpl:109,124,162` use `outline-none focus:border-accent`, while the CRUD forms add `focus:ring-1`. This is below the 3:1 focus-indicator guidance.
- **A3 [A] Sign-in links are tiny targets on mobile:** "Forgot your password?" is 14px tall and 12px text, and "Create an account" is 20px tall (L142-147, L196-202).
- **A4 [C] The sign-in screen doesn't use the library.** It hand-rolls labels and inputs instead of `ui/label` / `ui/input` (and `ui/login_form.tsx` is installed but unused). It shares `Button` only.
- What is good:
  - `autocomplete` is correct (`username`, `current-password`, `new-password`).
  - Sign-up toggles on the same route ("Create your fieldops account"), with password requirements tied by `aria-describedby`.
  - An unreachable backend reads "Could not reach the sign-in service." in a `role=alert`.
  - `returnTo` is carried through, and sign-out lives in the user menu.
  - Not verified live: the dev IdP round trip and the TOTP step.

### States, 404, toasts

- **X1 [A] Nested `<main>`.** `nextjs/src/app/not-found.tsx:5` and `error.tsx:25` render `<main>` inside the shell's `<main>` (`app_shell.tsx.tmpl:91`), which gives two `main` landmarks. Both also use a 30px **bold** h1 against the app's 20px semibold page h1.
- **X2 [C] The root `loading.tsx` uses `bg-border` bars**, while every other skeleton uses `bg-surface-muted`. The bars are centred like a hero, not shaped like the shell it is loading.
- **X3 [K] The toast system exists but is silent on success.** The stack is mounted, `aria-live=polite`, and the `MutationCache` error chokepoint works. No CRUD page emits a success toast (`rg emitToast app components` returns no call sites).

### Mock data (affects every demo and screenshot)

- **M1 [B] Dangling foreign keys.** Forge bug e3cba04c.
  - In `jobs_gen.ts`, 5 of 10 `customerId` values are not in `customers_gen.ts`.
  - `technicianId` is `"sample_technician_id_N"` on 5 of 10 rows, although `technician_id` has `REFERENCES technicians(id)`.
  - Cause: `frontend_mocks.go:532` caps each entity at its first 10 rows independently.
  - Effect: half the jobs show "—" for Customer and Technician.
- **M2 [K] The data reads like a test fixture:** `sample_title_1`, `sample_name_1`, `1@1.1`, `$0.01`, "Jan 8, 2024". Forge deliberately won't guess meaning from column names, and `db/seeds/vocab.yaml` is the documented fix.
  - Two parts are derivable from declared rules, not guesses:
    - an `email` validate rule implies `user1@example.com`;
    - a `_cents` money column implies a plausible magnitude.
  - For marketing screenshots, ship a filled `vocab.yaml` in the demo project rather than changing forge's no-guess stance.
