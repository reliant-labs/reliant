- `--fixtures <dir>`: your OWN directory of extra `*.js` fixture files, loaded

## Writing fixtures

A fixture file is plain browser JS that registers answers by Connect procedure:

```js
(function () {
  var fx = window.__fx, t = fx.t;           // t.iso(msAgo), t.MIN/HOUR/DAY
  fx.add({
    'reliant.v1.ChatService/ListChats': { chats: [ /* proto3 JSON, camelCase */ ], total: 1 },
    'reliant.v1.ChatService/GetChat': function (req) { return { chat: byId[req.chatId] }; },
    'controlplane.v1.BillingService/GetX': fx.has('errors')
      ? { __error: { code: 'unavailable', message: 'billing is down' } }
      : { /* ... */ },
  });
})();
```

- Keys are `<proto package>.<Service>/<Method>`: `reliant.v1.*` (the product
  API), `controlplane.v1.*` (billing, machines, orgs, deploy, observability).
- Bodies are **proto3 JSON** (camelCase field names, enums as their full
  names like `DAEMON_STATUS_ACTIVE`, int64 as strings, timestamps as ISO
  strings). Field names: `frontends/web/src/gen/**/<file>_pb.ts`.
- Special values: `{ __error: { code, message } }` (a Connect error; `code`
  is the snake_case Connect code), `{ __delay: 3000, ...body }`,
  `{ __pending: true }` (never answers: a permanent loading state),
  `{ __stream: [msg, ...], __end: true }` (connect+json server stream).
- A unary RPC with **no fixture answers `{}`** (empty lists, zero values) —
  the real "nothing here yet" path, so empty states render for free.
- Any stream without a fixture stays **open with no messages**, like an idle
  live subscription.
- **Binary-proto streams** (`reliant.v1.StreamingService/StreamChatUpdates`,
  `StreamUserUpdates`, which carry chat content and live state): answer with
  `{ __type: 'reliant.v1.ChatStreamEvent', __stream: [ {snapshot: {...}}, {caughtUp: {...}} ] }`.
  `harness/codec.js` (bundled from the app's own generated schemas by
  `build-codec.sh`) encodes the JSON to binary and decodes the request, so a
  function fixture receives `req.chatId`. A chat's messages come from the
  `snapshot.messages` of `StreamChatUpdates` (see `fixtures/10-models-chats.js`).
  Messages are `reliant.v1.Message` JSON; every string field must be a string
  (never `undefined` inside an array element the engine cannot strip).
- **What did the page ask for?** In DevTools:
  `window.__fx.unknown` (procedures with no fixture, with counts),
  `window.__fx.log` (every request), or add `?fxlog` to the URL for a console
  line per RPC. That is how you find what a surface needs.

## Scenarios (URL switches)

`?fx=<name>[,<name>]` selects scenarios for the tab (kept in
`sessionStorage`; `?fx=clear` resets). Scenarios are read **at page load**:
an in-app (SPA) navigation to a `?fx=` URL does nothing until you reload. If
a switch does not seem to apply, `reload` the page. Fixture files branch on
`window.__fx.has('<name>')`. Shared ones:

| `?fx=` | Effect |
|---|---|
| `onboarding` | `onboardingCompleted=false`, no projects/daemons, no subscription: the first-run flow |
| `empty` | Signed in, onboarded, nothing created yet (no project, chats, machines, workflows) |
| `signed-out` | No Supabase session: the sign-in screen |
| `errors` | Fixtures that honour it answer Connect errors |
| `slow` | Fixtures that honour it answer after a delay (loading states) |

Add your own in your fixture dir (`fx.has('my-case')`). Other URL switches:
`?theme=light|dark`, `?scheme=black|blue|neutral|slate|teal|purple|...`
(the app's Appearance schemes; default is the app's own default, pure-black
dark), `?fxbadge=0` hides the small "review harness" corner badge for clean
captures.

## Mobile vs desktop surface

The app sends phones to `/m/*` (`lib/mobileRedirect.ts`: narrow width, or
`(pointer: coarse), (hover: none)`). Headless Chrome can report
`hover: none`, and after `emulate` with `mobile,touch` the page keeps
reporting it even after the emulation is cleared, so desktop routes bounce
to `/m/...`. For desktop, open a fresh page (`new_page`) or add `?desktop=1`
(persisted opt-out). For mobile, `emulate` with viewport
`390x844x2,mobile,touch`; to see the desktop layout squeezed to phone width
instead, `resize_page` to 390 on a page that never emulated touch, with
`?desktop=1`.
