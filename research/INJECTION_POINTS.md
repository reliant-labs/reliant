# Engine injection points — what reaches the LLM beyond the workflow YAML

Research snapshot against current `main` (tools filter enforced, readonly tier removed).
Every claim below cites FILE:LINE in `reliant/`.

Legend for **Source**: `declared` = written by the workflow author; `config` = derived from
project/user config or DB records; `hardcoded` = literal text in Go (or an embedded `.txt`).

## 2. System prompt assembly, in wire order

For an Anthropic Claude-Code-keyed request the provider receives, in order:

1. **Spoof block 0** — billing header, regenerated per request (`claude_prompts.go:62-69`). *hardcoded*
2. **Spoof block 1** — `identity.txt`: `You are Claude Code, Anthropic's official CLI for Claude.` *hardcoded*
3. *(fable-5.1 only)* **reporting-outcomes block** (`ccprompts/reporting_outcomes.txt`). *hardcoded*
4. **Spoof agent block** — `agent_lean.txt` / `agent_verbose.txt` / `agent_fable51.txt`. *hardcoded*
5. **Spoof output block** — `output_lean.txt` etc. *hardcoded*
6. **Reliant segment 1** — persona + working dir + multi-repo hint + skills announcement, plus the retry reminder when attempt > 1 (`call_llm.go:2128-2183`). *hardcoded + config*
7. **Reliant segment 2** — `args.system_prompt`. *declared*

Non-Claude-Code Anthropic drivers skip 1–5 (`anthropic/base.go:676-698` only wraps caller
prompts with cache control). OpenAI/Codex append `openai_prompt.txt` as a **final** block after
6 and 7 (`openai_prompts.go:37-44`).

### The hardcoded persona, verbatim (`call_llm.go:2129-2183`)

> You are Reliant, a world class Software Engineer with advanced reasoning and capabilities. Note: it is very likely you are working in parallel with other agents, potentially in the same directory, or across multiple git worktrees. Please be careful of other's work. Be extremely careful with destructive commands that can discard another agent's uncommitted work, such as git checkout, git stash, and git reset.
>
> IMPORTANT: Your working directory is: `<workingDir>`
> This is an absolute path and it is the root of the project you are working on. Every relative path you use resolves against it, and shell commands start there. Read a project file by joining it to this root (`<workingDir>/README.md`) or by its plain relative path (README.md). NEVER guess a project root and never write a placeholder path such as /path/to/project — the real one is on this line.
>
> This project has multiple nested repos. Tools that take a `repo` parameter accept these values:
> - root (project root)
> - `<repo name> (<relpath>)` …
> Omit `repo` to inherit the chat's bound worktree.
>
> *(then)* `\n\n<system-reminder>\nAvailable skills (use the skill tool to load):\n- <path>: <desc truncated to 77 chars>[ (has sub-skills)]…\n</system-reminder>`

### The retry reminder, verbatim (`call_llm.go:2732-2739`)

> `<system-reminder>`
> This is retry attempt %d after a previous streaming failure (likely a truncated response from the LLM API). The previous attempt's response was too long or got cut off mid-stream. Please try a different approach:
> - Use fewer tool calls per response
> - Keep individual tool call inputs shorter
> - Break complex operations into multiple turns rather than one massive response
> `</system-reminder>`

### The preloaded-skills preamble, verbatim (`call_llm.go:2917-2926`)

> `<preloaded-skills>`
> The Reliant harness loaded the following skills into this conversation before your turn began. You did NOT call the skill tool for them and you do not need to — their full contents are reproduced verbatim below, exactly as the skill tool would have returned them.
>
> If your instructions name any skill listed here, that instruction is ALREADY SATISFIED. Do not load it again, and do not read its absence from your own tool calls as a mistake you need to correct.

### The memory preamble, verbatim (`call_llm.go:2868`)

> `# User defined rules, memories, and context`
>
> `You must adhere to the user's defined rules and context below at all times.`
>
> followed by `## Global Context` and `## Project Context` sections.

### The code_context nudge, verbatim (`code_context_nudge.go:46-52`)

> `[IMPORTANT] This grep is a symbol lookup. Run `code_context(symbol: "%s")` NOW instead of grepping further — one call returns the definition, its source, every caller and callee (3 levels deep), and the interfaces involved.`
> `Your grep CANNOT answer "who calls this": a call site never names its receiver's type, so it matches every same-named method and the error compounds at each hop. Continuing to grep costs a turn per hop for a worse answer.`

## 3. Message injection, by layer

**Durable (written to `messages`)**
- Compaction summary, role `system`, new context sequence (`compact.go:157-183`).
- Interrupted-turn partial assistant message (`call_llm.go:340-395`).
- Content-free-turn workflow error row (`call_llm.go:609-645`).

Nothing else the engine adds is persisted.

**In-memory only (re-sent every turn, never stored)**
- Memory system message (#9) and per-repo memory messages (#11) — prepended to history
  (`call_llm.go:1132-1147`).
- Preloaded-skill seed spliced after the *first* user turn (`call_llm.go:1195`,
  `insertSeededMessagesAfterFirstUserTurn` at `call_llm.go:3100-3120`).
- Skill-suggestion reminder mutated **into** the last user message's text
  (`injectReminderIntoLastUserMessage`, `call_llm.go:2826-2841`) — note this rewrites the
  user's own words in the request, not as a separate block.
- Compaction's ephemeral trigger user message (`compact.go:381-390`).

**Into tool results** — code_context nudge (#22), batch truncation marker (#23), unattended
ask_user answer (#24).

## 4. Memory files

Read on the **daemon**, not the server (`internal/toolexec/daemonruntime/config_store.go:56-117`):

- `~/.reliant/reliant.md` → `GlobalMemoryMD` (`config_store.go:61`)
- `<project>/reliant.md` → `ProjectMemoryMD` (`config_store.go:62`)
- `<repo>/reliant.md` + `<repo>/reliant.local.md` per nested repo → `RepoMemories`
  (`runtime.go:1725-1766`)
- Forge framework memory auto-prepended when `forge.yaml` exists (`forge_memory.go:25-49`)
- Also snapshotted: `config.yaml`, `.reliant/config.yaml`, `.reliant.local/config.yaml`,
  `mcp.json` at three scopes.

Paths are **hardcoded**, not configurable. `CLAUDE.md` and `AGENTS.md` are **not** read as
memory — they only appear as skill roots (`.claude/skills`, `.codex/skills`, `.agents/skills`,
see `internal/skills/catalog/`). The snapshot is pushed server-side via
`internal/grpc/services/tools_daemon.go:1311-1318`. The engine decides placement: global+project
memory become one `System` message, repo memories one `System` message each, all at the head of
history.

## 5. Skills — three separate paths

1. **Announcement** (#4): the *entire* catalog's names+descriptions is listed in the system
   prompt on every turn, whether or not the author asked (`skill.go:540`). Pure injection.
2. **Preload** (#13): driven by the declared `skills:` arg — the bodies are seeded as a fake
   user turn. Declared trigger, hardcoded envelope.
3. **Suggestion** (#15): token-scores the catalog against the last user message and appends up
   to 5 suggestions. Fires *only* when nothing was preloaded (`call_llm.go:2795`). Pure
   injection.

So yes — there is automatic skill injection the author never asked for, in two forms (#4, #15).

## 6. Tool description mutation

- `shell`: description selected at request time from the executing **daemon's** OS
  (`handlers/shell_platform.go:43`, `tools/shell_platform.go:57`). The Unix body is ~300 lines
  and contains heavy editorial guidance: "⛓️ CHAIN PROBES", "🚫 NEVER SCAN THE FILESYSTEM",
  "prefer the View tool over cat/head/tail", plus a "code_context tool, not this one" section
  (`tools/shell.go:180-277`).
- `load_tool`: description gains a JSON list of deferred tools appended at runtime
  (`load_tool.go:42-56`), driven by `DeferredToolNames` at `call_llm.go:1081`.
- No other tool rewrites its description; MCP tool descriptions pass through unchanged.

Shell *behavior* is also mutated: `unscopedSearchRefusal` and `ripgrepReplaceRefusal` refuse
commands before dispatch and return instructional refusal text (`tools/shell.go:335-345`).

## 7. Response / behavior curation

- **Forced tool choice**: `llm.ForceToolChoice` pins a single tool across all drivers
  (`internal/llm/types.go:151-160`; e.g. `openai/driver.go:294`, `anthropic/claude_code.go:718`).
- **Response tool**: injected outside the tools gate so `tools: false` still gets structured
  output (`call_llm.go:1042-1057`). Declared.
- **Retry nudge**: #6.
- **Compaction**: summary generated with a hardcoded summarizer prompt and written back as a
  durable system message with a hardcoded continuation preamble (#25, #26).
- **Turn yielding**: an assistant-tailed history returns an empty output instead of calling the
  provider (`call_llm.go:1305-1330`) — a behavior change the author cannot see or control.
- **Content-free turn**: engine composes user-facing prose for refusal / max-tokens /
  pause-turn (`call_llm.go:670-690`).
- **Unattended ask_user**: the engine answers on the model's behalf with instructions to
  self-resolve and not ask again (`unattended.go:82-102`).
- No auto-continuation or stall-detection prod was found.

## 8. Per-turn vs once

Essentially **everything is per-turn**. Recomputed on every `call_llm` invocation: the whole
system prompt (#1-#6), memory and repo-memory messages (#9-#11), the skill seed (#13), skill
suggestions (#15), shell platform resolution (a DB read per turn, `call_llm.go:1780`), the
deferred-tool list (#17), the full tool list, and history repair/trim (#28). The only "once"
items are the daemon config snapshot (pushed on content-hash change) and the compaction summary.

Determinism caveats: the Claude Code billing header mints a fresh `cch` and `cc_prompt_id` per
request (`claude_prompts.go:36-68`), and skill suggestions vary with catalog state, so two
identical runs do not produce byte-identical requests.

## 9. Judgment: keep vs IDE-only

**Clearly IDE/chat-flavored — a headless data-pipeline user would not want these:**
- #7 Claude Code spoof. This is the single largest injection and the most inappropriate for an
  API user: it asserts `You are Claude Code, Anthropic's official CLI`, describes `/slash`
  commands, a `/tmp/scratchpad`, `! <command>` prompt prefixes, `/code-review ultra` billing,
  an `Environment` block naming `Platform: darwin`, `Shell: zsh`, and a **frozen literal
  `gitStatus` from someone's machine** (`ccprompts/output_lean.txt:20-75`). None of it is
  computed; it is all captured text sent verbatim to every request. It exists for
  prompt-cache/fingerprint parity on OAuth keys, which is a billing concern, not an agent one.
- #1's multi-agent/worktree warning and #2's worktree path framing.
- #4 and #15 skill announcement/suggestion — an API user declared their skills already.
- #22 code_context nudge — tuned for interactive coding agents.
- #8's `openai_prompt.txt`, which includes Codex CLI personality, approval-escalation language,
  and "styled by the CLI" output rules (`openai_prompt.txt:16-20,183`).

**Genuinely needed by any agent:**
- #5, #16 (declared), #28 (history repair/trim/role normalization — a correctness requirement),
  #18 shell platform accuracy, #17 deferred-tool advertising, #23 batch truncation,
  #26 compaction mechanics, #3 multi-repo hint.

**Defensible but should be opt-in:**
- #2 working-directory statement (real bug fix, but the prose is heavy), #9-#12 memory files,
  #19/#20 forced tools, #6 retry hint, #24 unattended answer, #25 compaction preamble,
  #29 silent turn yield.

**Recommended engine-mode boundary:** default OFF for #1, #2's prose, #4, #6, #7, #8, #13's
envelope, #15, #19, #20, #22, #24, #27 — keeping #3, #5, #16, #17, #18, #23, #26, #28. That
leaves the model with exactly the author's declared system prompt, the author's messages, an
honest tool surface, and mechanically-required history hygiene.
