# Chat timeline: main vs old #3010 vs new #3010

Compared on the visual fixtures in `frontends/web/e2e/visual/fixtures/chat.ts`:

- **chat-tools** (`TOOLS_TURNS`): m2 `[thinking, text, grep×3, glob, view×5]`, m3 `[redacted, text, edit×4]`,
  m4 `[text, shell×2, grep, text]`.
- **the long fixture chat**: reads, edits with diffs, a failed shell call it recovers from, thinking, two
  parallel `spawn`s, an `ask_user`, an approval.
- **chat-failure** (`FAIL_TURNS`): `[text, view, grep, shell, shell(failed)]`, then a turn-stopping provider
  error.

"main" means `origin/main` (and C1, `feat/web-chat-conversation-frame`, which keeps main's grouping).
"old #3010" is `e5c71e614`. "new #3010" is this rework.

| Behaviour | main | old #3010 | new #3010 | Why |
|---|---|---|---|---|
| **A run of tool calls** (the work between two pieces of prose) | Always one `TurnWorkFold`, collapsed by default, live or not, however short. | ≤5 steps: each call shown inline as its own row (no fold). More than 5: one summary row. | **main's**: always one fold, collapsed by default, however short (even one call). `INLINE_STEPS_MAX` and the `inlineStepsMax` prop are gone. | Owner: main's collapsing is better. A turn reads as narration with one quiet line where the agent worked, whatever its length. |
| **The fold's look** | Bordered-less button, `text-xs`, chevron on the left, a pulsing `bg-primary` dot while live, `font-medium` headline. | `QuietRow`: 16px icon slot (`ListTree`, a spinner while live, `XCircle` on failure), `text-ui` muted sans, chevron revealed on hover, end time and branch revealed on hover. | **#3010's** `QuietRow` summary row. | Polish that fits inside main's structure. |
| **Summary headline, counts, elapsed** | `formatTurnWorkHeadline` / `formatTurnWorkCounts` / `formatTurnWorkElapsed` ("Activity · 5 files read · 3 searches", `1:12`), `N failed steps`. | Same functions, but only for runs over 5 steps. | Same functions on every run, **plus the run's edit total** (`+6 −6`) after the counts. The total is visual only: the accessible name stays "Activity, 4 files edited", so a stub read (elided edit inputs) and the full transcript still name the fold identically (`TurnWorkFold.elidedBodies.test.tsx`). | main's summary is the owner's; the edit total is a #3010 improvement that fits. It counts an elided edit once its body has been read. |
| **The live line while streaming** | Headline is the current step ("Reading src/a.ts…"), held ≥1.2s per step (`useMinimumDwell`), elapsed ticks each second, fold stays collapsed. | Same, but only once the run passed 5 steps; a short live run showed its rows growing in place. | **main's**, on every run, with #3010's spinner icon in place of the pulsing dot. | The fold always carries the live state now. |
| **Read/search grouping inside the fold** | `ChatMessage.renderToolRun`: a run's read-only calls (`view`, `grep`, `glob`, `ls`, `websearch`, `fetch`, `diagnostics`, …), when 2+, become one `ToolExecutionCollapsibleGroup` "Explored 5 files 3 searches 1 listing" (a bordered, tinted box); rendered first, before the run's other calls. | `ToolExecutionCollapsibleGroup` deleted, `isReadOnlyTool` / `generateReadOnlyToolsSummary` deleted; every call its own row. | **Restored**: same rule, same wording, same open/close behaviour (`useToolGroupExpansion`: open while a read runs or one failed, closed when done, always closed on the phone unless an approval waits), restyled as a `QuietRow` (Eye icon, spinner while live, `XCircle` + "N failed" on failure) that also batch-reads elided bodies when opened, like `ToolExecutionGroup`. One improvement: each group sits **where its first call ran** instead of always first, so a read after an edit is not shown before it. | main's grouping is the structure; the reorder was an accident of `filter()`, not a choice. |
| **Grouping of the run's other calls** | When the message made 2+ calls and the run has 2+ non-read calls, one `ToolExecutionGroup` ("Edited src/pricing/config.ts and 3 other tools"), bordered box. | Desktop: every call its own row. Mobile: a settled, successful run (`isQuietToolRun`) is one group row. | **Restored main's rule on desktop**, as the `QuietRow` group row #3010 already had; mobile keeps the `isQuietToolRun` rule (same as main). | main's structure. Note: inside a fold whose run is all edits this nests fold → group → row; that is main's behaviour and is kept. Dropping the inner group when it is the fold's only row is a possible follow-up. |
| **Each call row** | Bordered card per call (`ToolExecution`), name + args, status pill. | `QuietRow`: tool icon (`toolRowIcon`), sans verb, mono target, `+4 −1` on edits, status word, duration on hover, no card or stripe; detail (diff, output) closed by default. | **#3010's** row, inside folds and groups. | Polish. |
| **`+4 −1` on edits** | None. | On each edit row (`editDiffStat`). | Kept on rows (now via a shared `DiffStatText`), and summed on the fold (`sumDiffStats`). | Improvement that fits. |
| **Narration visibility** | Never folded: `simplifiedTurns` cuts a message into prose / fold / prose; prose is always on screen. | Same. | Same. | Owner decision, and main already did it. |
| **Thinking** | Not rendered at all (`messageProcessor` dropped `THINKING`). | A collapsed "Thought" row (`ThoughtRow`); thinking treated like prose: always outside folds, so `[thinking, tools]` per LLM call split one turn into Thought / fold / Thought / fold. `REDACTED_THINKING` never renders. | A collapsed "Thought" row that **goes with what it led to**: thinking that leads into tool calls (the next thing the message says is a call), or trails an open run of calls, is a row **inside** the fold; thinking that leads into prose stays on screen just above it. Thinking before a surfaced call (a question, an approval) stays on screen before its card. `REDACTED_THINKING` still renders nothing. | Keeps main's one-fold-per-run structure for interleaved-thinking models, while keeping #3010's Thought row. In chat-tools, m2's thinking leads into prose, so it stays above it. |
| **Which items are cards** | Nearly everything: each tool call, read group, retries, info, compaction, system notices, run steps, dividers were bordered/tinted cards. | Cards only for approvals, questions (`ask_user`, `request_machine`), sub-agents, and the turn-stopping failure; retries/info/compaction/system notices/run steps/dividers are quiet rows. | **#3010's** card set, unchanged. | Polish; not about grouping. |
| **What is surfaced out of the fold** (`surfacedExecutions`) | `ask_user`, `request_machine`, a call awaiting approval, `generate_image` / `generate_video`, a drafted automation once its draft is back, a deploy that put something live. A `spawn` stayed folded. | main's list **plus `spawn`** (its sub-agent card). `spawn_send` / `spawn_status` stay folded. | **#3010's** (main's list + `spawn`). | The brief keeps sub-agent cards, and a card with a Cancel button inside a closed fold cannot be reached or seen; a running sub-agent is an object the user may need to act on. |
| **Cancel on running sub-agents** | The spawn row inside the fold had its cancel control. | Sub-agent card with Cancel (B1 audit restore, `ToolExecution.subAgentCard.test.tsx`). | Kept. | B1 audit. |
| **Sub-agent mail and completions** | Folded into the run as events (`isFoldableActivityMessage`), shown in order in the fold body. | Same. | Same. | Unchanged. |
| **The turn-stopping failure** (chat-failure) | `WorkflowErrorMessage` card; the fold shows "1 failed step" and an explanation line when opened. | Same, restyled card, `settingsPath('ai')` link (B1). | Same as old #3010. The failed `shell` is a row inside the fold; the fold shows `XCircle` and "1 failed step". | Unchanged. |
| **Detailed (non-simplified) transcript** | No folds; read/other grouping as above. | No folds; flat rows. | No folds; main's read/other grouping, #3010's rows. | Same `renderToolRun`. |
