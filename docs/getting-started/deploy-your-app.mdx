Reliant deploys web apps, static sites, backends, APIs and databases with sign-in, and gives each one releases, environments and observability from the first deploy. [Forge](/forge/overview) is the open-source (Apache-2.0) CLI and MCP server that builds and ships the app. [Reliant Cloud](/hosting/overview) hosts it and monitors it. Your first deploy needs no account.

## For AI agents

```markdown
MCP server: `npx -y @reliantlabs/forge mcp` (tool: `deploy_claimable`). Docs as markdown: append `.md` to any page URL.
```

## Two steps

<Steps>
  <Step title="Get Forge">
    ```bash
    npm i -g @reliantlabs/forge
    ```

    Or skip the install and prefix each command with `npx -y @reliantlabs/forge@latest`. Homebrew and a shell installer are in [Deploy without an account](/forge/deploy-without-an-account#get-forge).
  </Step>
  <Step title="Run forge start and follow it">
    ```bash
    forge start
    ```

    `forge start` prints the one next command for the directory you are in. It creates and changes nothing. For an app that is already there (a Vite app, a Next.js static export, or any app with its own Dockerfile) that command is:

    ```bash
    forge env deploy prod --claimable
    ```

    It adopts the app where it stands (adding `forge.yaml` and `deploy/kcl/`, leaving your files alone), builds it, publishes it, and prints a live URL and a claim link. Open the claim link within 72 hours and sign up (free) to keep the deploy. In an empty directory, `forge start` names the command that creates a site or an app with an API instead.
  </Step>
</Steps>

The same in one line, with nothing installed:

```bash
npx -y @reliantlabs/forge@latest env deploy prod --claimable
```

A no-account deploy fits one static site, or one service with one database. Its limits and exit codes are in [Deploy without an account](/forge/deploy-without-an-account). To let a coding agent do it, see [Deploy your app with a coding agent](/guides/forge/deploy-with-a-coding-agent).

## What you can deploy

### Web apps and static sites

Reliant Cloud hosts Vite apps, Next.js static exports and static sites behind a CDN, with [custom domains and HTTPS](/hosting/custom-domains) and a [preview environment per pull request](/hosting/preview-environments). Static sites are free in one organization per person, with no limit on how many: 1 GiB of storage per site, 10 GiB in total and 10 GiB of traffic a month. A Next.js app builds as a static export.

- [Deploy a static site to a CDN](/guides/forge/deploy-static-site-cdn)
- [Adopt an existing Vite or Next.js app](/guides/forge/adopt-existing-vite-nextjs)

### Backends, APIs and workers

Deploy Go services that Forge generates, or any app in any language with its own Dockerfile. Workers and one-off jobs (such as the migration that runs before each rollout) run beside your services, and [secrets](/hosting/secrets) are kept per environment. Each release is built once and promoted by digest from dev to staging to prod, so prod runs the exact bytes staging ran.

- [Deploy a Go API with managed Postgres](/guides/hosting/deploy-go-api-managed-postgres)
- [Bring an existing app in any language](/guides/forge/bring-existing-app-any-language)
- [Promote a release from staging to production](/guides/hosting/promote-release-staging-to-production)

### Database plus auth

Each environment can have its own [managed Postgres](/hosting/managed-postgres), with continuous backups and point-in-time restore over the last 7 days (no-account deploys aren't backed up). [Managed identity](/forge/auth) gives your app sign-in for its own users with no auth server to run: passwords and passkeys on Reliant Cloud today. Magic links and Google or GitHub sign-in can be declared but aren't served on hosting yet. You can also bring Auth0, Okta, Keycloak, Supabase or Clerk.

- [Add sign-in with passkeys](/guides/forge/add-sign-in-passkeys)
- [Restore a managed Postgres database to a point in time](/guides/hosting/restore-postgres-point-in-time)

## What every deploy gets

- **Observability with no setup.** [Traces, logs and metrics](/hosting/observability), errors grouped into issues tied to the release that caused them, [continuous profiling](/hosting/observability/profiling), [session timelines](/hosting/observability/session-timelines) with opt-in, masked replay, default alerts and [product analytics](/forge/observability/product-analytics).
- **Releases that are judged.** `forge obs check` gives each deploy a pass, fail or inconclusive verdict; [health gates](/guides/hosting/gate-production-deploy-release-health) hold prod until staging proves a release healthy; rollback floors stop a deploy behind a breaking migration. [Recover from a bad deploy](/guides/hosting/recover-from-bad-deploy) by redeploying an earlier release.
- **Security checks.** Dependency and image scanning with `forge ci vuln-scan`; the [Vulnerabilities page](/forge/security/vulnerabilities) is rolling out. Forge lints migrations for unsafe changes before they ship.
- **Agents that run the lifecycle.** The [Forge MCP server](/hosting/observability/agents) lets Claude Code, Codex or Cursor deploy, lint and read production telemetry. [Autopilot](/guides/autopilot) reviews and security-reviews pull requests, turns issues into pull requests and investigates alerts. A person merges.

## No lock-in

Every piece is optional. [Deploy to your own Kubernetes cluster](/guides/hosting/deploy-to-your-own-kubernetes), [keep Helm, Fly.io or Cloud Run](/guides/hosting/keep-helm-fly-cloud-run) and still get releases and gates, [send OpenTelemetry from any app](/guides/observability/send-opentelemetry-from-any-app), or bring your own database or identity provider. Forge works piece by piece in any repo, with no rewrite, and is Apache-2.0. [Escape hatches](/forge/deploy/escape-hatches) covers the rest.

## Cost

- **The first deploy:** free, with no account, for 72 hours until someone claims it.
- **A static site:** one per person is free.
- **Observability:** 10 GiB of telemetry per organization per month is included; beyond that, ingestion is billed per GiB ([observability billing](/hosting/observability-billing)).
- **Services, workers and databases:** pay-as-you-go for CPU, memory and storage, with no base fee and a monthly budget you set ([billing](/hosting/overview#billing)). Rates are on the [pricing page](https://reliantlabs.io/pricing).
