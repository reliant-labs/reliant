These docs are also an MCP server. Connect it, and your coding agent searches and reads the documentation for Reliant, Forge and Reliant Cloud while it works, instead of answering from what it remembers about a flag, a limit or an exit code. The server is public and read-only: it needs no account, no token and nothing installed.

| | |
|---|---|
| **URL** | `https://docs.reliantlabs.io/mcp` |
| **Transport** | Streamable HTTP |
| **Name used on this page** | `reliant-docs` (any name works) |

In a Reliant chat you need none of this: every agent already has the docs as its built-in `reliant-docs` MCP server.

## Connect it

### Claude Code

```bash terminal
claude mcp add --transport http reliant-docs https://docs.reliantlabs.io/mcp
```

Add `--scope user` to have it in every project, not only this one. `claude mcp list` shows `reliant-docs` as connected once it answers.

### Cursor

Put this in `.cursor/mcp.json` for one project, or `~/.cursor/mcp.json` for all of them:

```json .cursor/mcp.json
{
  "mcpServers": {
    "reliant-docs": {"url": "https://docs.reliantlabs.io/mcp"}
  }
}
```

If the file already lists the Forge MCP server, add `reliant-docs` beside `forge` in the same `mcpServers` object.

### Codex

```bash terminal
codex mcp add reliant-docs --url https://docs.reliantlabs.io/mcp
```

Or add it to `~/.codex/config.toml` by hand:

```toml ~/.codex/config.toml
[mcp_servers.reliant-docs]
url = "https://docs.reliantlabs.io/mcp"
```

### Any other MCP client

Give it the URL as a streamable HTTP server. In VS Code, that is `.vscode/mcp.json`:

```json .vscode/mcp.json
{
  "servers": {
    "reliant-docs": {"type": "http", "url": "https://docs.reliantlabs.io/mcp"}
  }
}
```

In Claude on the web or desktop, add it under **Settings → Connectors → Add custom connector**.

## What the agent gets

| Tool | What it does |
|---|---|
| `search_reliant` | Searches every page and returns the matching passages, each with its title and link. |
| `query_docs_filesystem_reliant` | Runs read-only `rg`, `ls`, `tree`, `head` or `cat` over the pages as files, so the agent can read a whole page. The page at `/forge/quick-start` is the file `/forge/quick-start.mdx`. |
| `submit_feedback` | Reports a page that is wrong, outdated or unclear to the docs team. It is the only tool that sends anything, and it changes nothing. |

The server sees only the published pages. It cannot see your account, your projects or your deploys.

To check it works, ask the agent: "Use the reliant-docs server: what does `forge obs check` exit with when a release regressed?" It should call `search_reliant` and answer from [Querying with forge obs](/hosting/observability/forge-obs).

## The docs server and the Forge MCP server

They do different jobs, and an agent working on a Forge app wants both:

- **The docs server** (this page) answers questions. It reads documentation and nothing else.
- **The Forge MCP server** (`npx -y @reliantlabs/forge mcp`) acts on your repository: it deploys, lints, generates and reads your app's telemetry. [Deploy your app with a coding agent](/guides/forge/deploy-with-a-coding-agent) installs it, and [Connect Claude Code or Cursor to Forge over MCP](/guides/forge/connect-claude-code-cursor-mcp) lists its tools.

An agent with no MCP client at all can still read the docs: [llms.txt](https://docs.reliantlabs.io/llms.txt) is an index of every page, and each page is available as Markdown by adding `.md` to its URL.
