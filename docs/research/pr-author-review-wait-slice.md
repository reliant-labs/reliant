## Explicit activation holds / boundaries

This is a DRAFT/off stage. The experimental node is not added to the workflow-builder sidebar catalog; its typed YAML/runtime path exists for explicit registration/test use. **No application root constructs/registers these activities, producer or optional publication normalizer.** Hand-authoring the experimental node against an unconfigured production worker is unsupported and will fail on missing PRReviewWaitArm activity; this is not a deployable live feature. Existing Chat A automation is untouched. No deployment, activation, merge or release. A public GitHub ingress event adapter and production reviewer/check policy are not wired; merge-queue/check/closure provider adapters remain future work, though the inbox/runtime state vocabulary supports closed/unavailable. GitHub review IDs order review creation; this is not a universal aggregate policy for multiple reviewers/dismissals/checks. Live readiness labels are not published: Ready is a durable internal stamp only.

Retention remains an owner-policy activation hold; no expiration/GC duration invented. The worktree cleanup timing is not binding retention. Post-provider-write/timeout reconciliation remains a hold inherited from #1709. No automatic code claims backlog PR authorship from body/trailers.

Continue-as-new proof is implemented, not a global CAN blocker. A currently waiting DAG future naturally stays pending. Fully exercising rollover of the entire DynamicWorkflow graph and authenticated production event-to-worker delivery remains necessary before activation; unit history proof plus subscription cursor tests do not claim a live production closed loop.
