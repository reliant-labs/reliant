Reliant is four products. Each has one job, and they work best together: Forge builds and ships the app, Reliant Cloud runs it and watches it, Reliant Workflows put agents to work on the code and on what Cloud reports back, and Reliant Engine will put those workflows inside your own product. You can use any of them without the others.

<CardGroup cols={2}>
  <Card title="Forge" icon="hammer" href="/forge/overview">
    Forge is guardrails for apps. It is an open-source (Apache-2.0) framework, CLI and MCP server that supercharges any agent harness: Claude Code, Codex, Cursor, a harness you wrote, or CI. It scaffolds Go services, React frontends and SQL migrations into the right places, lints for your architecture and for unsafe migrations, tests against a real Postgres, and builds each release once and promotes it by digest. Use it piece by piece in any repo, in any language, with no rewrite. Deploy any app with no account: in a Vite or Next.js app, or an app with its own Dockerfile, run `npx -y @reliantlabs/forge@latest env deploy prod --claimable` to get a live URL and a claim link that is good for 72 hours.
  </Card>
  <Card title="Reliant Cloud" icon="cloud" href="/hosting/overview">
    Reliant Cloud is a hosting and delivery platform: GitLab meets Vercel meets Supabase, powered by Forge. It hosts your app with managed Postgres, static hosting with a CDN, custom domains with HTTPS, preview environments and managed secrets. It monitors what it runs with traces, logs, metrics, alerts, errors grouped into issues tied to the release that caused them, continuous profiling, and opt-in, masked session replay. It manages releases: each one is built once, promoted by digest, judged by its own health check, and kept above a rollback floor that a breaking migration sets. It scans dependencies and images for vulnerabilities, and builds profile-guided binaries from production profiles (`forge pgo pull`). Test reports, code coverage and flaky-test detection are coming, as is automatic weekly profile-guided optimization.
  </Card>
  <Card title="Reliant Workflows" icon="bot" href="/workflows/overview">
    Reliant Workflows is an agent automation platform. A workflow is a YAML pipeline that mixes agents with deterministic steps, approvals and loops, runs on any model, and starts from a schedule, a webhook, a GitHub, Slack, Gmail or Twilio event, or a hosted alert. Workflows power Autopilot, which reviews and security-reviews every pull request, turns a labelled issue into a tested pull request, answers review comments, and investigates alerts into issues an agent can fix. Autopilot never merges or releases on its own today; built-in merge and release workflows are coming.
  </Card>
  <Card title="Reliant Engine (coming soon)" icon="cog" href="/getting-started/concepts#reliant-engine-coming-soon">
    Reliant Engine is coming soon. It will let you embed Reliant Workflows in your own product, white-labelled, so your users run agent workflows inside your app without seeing Reliant. It is not available yet.

## Deploy with your agent

Install the Forge MCP server:

- Claude Code: `claude mcp add forge -- npx -y @reliantlabs/forge mcp`
- Codex: `codex mcp add forge -- npx -y @reliantlabs/forge mcp`
- Cursor: add to `.cursor/mcp.json` (or `~/.cursor/mcp.json`): `{"mcpServers":{"forge":{"command":"npx","args":["-y","@reliantlabs/forge","mcp"]}}}`
- Gemini CLI: `gemini extensions install https://github.com/reliant-labs/forge`

Then paste this prompt:

> Deploy this app with Reliant Forge. Run `npx -y @reliantlabs/forge@latest env deploy prod --claimable` (or call the forge MCP server's `deploy_claimable` tool), then give me the live URL and the claim link. The claim link expires in 72 hours; treat it like a password.

No MCP server: `npx -y @reliantlabs/forge@latest env deploy prod --claimable` works on its own. [Deploy your app with a coding agent](/guides/forge/deploy-with-a-coding-agent) walks through it, and [Deploy without an account](/forge/deploy-without-an-account) has the limits. [Deploy your app](/getting-started/deploy-your-app) covers what web apps, backends and databases with sign-in get on Reliant Cloud.

## How the products fit together

Reliant is also an agentic development environment (ADE). Like Cursor or Claude Code, it lets you chat with AI agents that read, write, and run code in your project. Unlike them, it adds **programmable workflows** (Reliant Workflows): multi-step, multi-agent processes defined in YAML that reduce the human in the loop and produce higher quality code more consistently. Its servers run the agents, and a [machine](/machines/overview) you choose, your own computer or a Reliant cloud machine, does the hands-on work with your code.

[Forge](/forge/overview) is what those agents build on. A forge project has a fixed, well-known structure, so an agent does not have to invent how an app is configured, tested, deployed or monitored. It runs `forge scaffold` and gets a service, a database table and a frontend page; `forge env up dev` and gets a running stack; `forge env deploy staging` and gets a release on [Reliant Cloud](/hosting/overview) with a managed Postgres and a URL; and `forge obs check` to find out whether the release is healthy. Forge is built into the `reliant` binary, so `reliant forge ...` works wherever Reliant does, already signed in as you.

The products meet in a few places. The **Build an App** workflow scopes an app with you and scaffolds it as a Forge project. **Move to Forge** ports an existing codebase into one. The **Apps** and **Observability** areas of the Reliant app show the releases, environments, logs, traces and alerts of what you deploy on Reliant Cloud. And a workflow can call a deployed Forge app's API, so an agent decides while the app holds the data and enforces the rules.

For the tools these products replace, and how one declared model of your app does it, see [What Reliant replaces](/getting-started/what-reliant-replaces).

## Why workflows matter

In a typical AI coding tool, you are the orchestrator. You prompt, read the output, decide the next step, prompt again. For simple tasks that's fine. For anything involving multiple steps — refactoring, code review, test-driven development, release prep — you're doing the same manual choreography every time.

Workflows automate that choreography. You define the steps, the agents, and the logic once. Then you run it.

<Tabs>
  <Tab title="Without workflows">
    ```
    1. Ask AI to review the code        (copy-paste diff)
    2. Read the review                   (manually)
    3. Ask AI to check for security      (copy-paste diff again)
    4. Read that review                  (manually)
    5. Synthesize both reviews           (you do this in your head)
    ```
  </Tab>
  <Tab title="With a Reliant workflow">
    ```yaml
    # .reliant/workflows/code-review.yaml
    name: code-review
    entry: [security_review, style_review]   # both start at once

    nodes:
      - id: security_review
        type: workflow
        ref: builtin://agent
        thread:
          mode: new
        args:
          system_prompt: "Review for security issues..."

      - id: style_review
        type: workflow
        ref: builtin://agent
        thread:
          mode: new
        args:
          system_prompt: "Review for code quality..."

      - id: reviews_done
        type: join          # wait for both

      - id: summarize
        type: workflow
        ref: builtin://agent
        args:
          system_prompt: "Synthesize the reviews..."

    edges:
      - from: security_review
        default: reviews_done
      - from: style_review
        default: reviews_done
      - from: reviews_done
        default: summarize
    ```
    Two agents review in parallel, a third summarizes. One click, every time.
  </Tab>
</Tabs>

## What ships with Reliant

Reliant includes built-in workflows you can use immediately. Pick one from the workflow selector in the chat composer:

| Workflow | What it does |
| --- | --- |
| **Agent** | The default. Chat with an AI agent that can read, edit, search, and run commands in your project. |
| **Get It Right** | For complex changes in an existing codebase. Loops implement → lint/test/build → review, undoing bad attempts, until the reviewer passes the work. |
| **Best of Three** | Three agents implement the same task in isolated workspaces. A reviewer picks the winner or merges the best parts. |
| **Build an App** | Scopes an app with you, scaffolds it with Forge (services, workers, web or mobile frontends, static sites), then builds and verifies it end to end. |
| **Move to Forge** | Migrates an existing codebase into a Forge project, porting it one component at a time. |
| **Landing Page** | Scopes a landing page with you, writes it, reviews the copy and then the design, and serves it at a preview URL. |
| **Pitch Deck** | Builds an investor deck from your company website, with competitive research, a short founder interview, and a visual review pass. |
| **Create a Workflow** | Turns a conversation about what you want to automate into a working, tested workflow. |
| **Import from Claude Code / Cursor** | Brings useful configuration across from Claude Code, Cursor, Codex, or Windsurf. |

You can also build your own — see [Creating Custom Workflows](/workflows/custom-workflows).

## What you can build

Beyond the built-ins, workflows let you encode any repeatable multi-step process:

**Automated code review** — Parallel agents check security, style, and correctness. A third agent synthesizes findings into one review.

**Test-driven bug fixes** — Write a failing test, loop: attempt fix → run tests → retry if failing. Stops when tests pass or hits an attempt limit.

**Refactor with guardrails** — Analyze code for simplification opportunities, refactor, then verify that tests still pass before moving on.

**Competitive implementations** — Three agents solve the same problem with different approaches in isolated workspaces. A reviewer picks the best one.

**Plan debate** — A proposer and a critic alternate rounds, refining a plan until they converge. Better plans through adversarial thinking.

**Continuous autonomous development** — Pick a task from a spec, implement it, verify it, commit it, pick the next task. Hands-off until done.

## Config as code

Workflows are YAML files that live in `.reliant/workflows/` inside your repository. This gives you things no other ADE offers:

- **History** — Track who changed what workflow and when
- **Review** — Workflow changes go through PRs like any other code
- **Consistency** — Everyone on the team runs the same processes
- **Rollback** — Revert a broken workflow like any other commit

## Forge: what you get

Forge gives every project, from the first commit, the things that usually get bolted on late: structured logs, traces and metrics on every boundary, a Postgres schema with generated data access, linters and tests, CI, and `dev`, `staging` and `prod` environments. Deploying is one command to Reliant Cloud, which runs your services, workers and jobs with a managed Postgres, publishes frontends as static sites behind a CDN, and supports custom domains. A landing page or docs site with no backend is a complete Forge project too. See the [Forge overview](/forge/overview) for the full picture and [Reliant Cloud](/hosting/overview) for what it runs; current plans and prices are on the [pricing page](https://reliantlabs.io/pricing).
