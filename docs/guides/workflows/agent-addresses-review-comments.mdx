By the end of this guide, when you or someone you trust reviews a pull request you opted in, an agent changes the code to address the feedback, runs your fast checks, pushes a commit to that pull request's branch and replies in each review thread. A person still approves and merges.

This is `autopilot-review-responder`, one of the [Autopilot](/guides/autopilot) built-ins. It works in a checkout, so it runs on a [machine](/machines/overview) that holds a clone of the repository.

## Before you begin

- The `reliant` CLI, v1.21 or later, signed in ([Sign in and tokens](/cli/sign-in)), and `gh` for the GitHub side.
- The Reliant GitHub App on the repository ([GitHub integration](/integrations/github#access)), and a connected machine with a clone of it in a Reliant project. [Turn issues into pull requests](/guides/workflows/github-issues-to-pull-requests) sets up the same project and machine.
- In an organization: an organization AI account that can run the `flagship` model, the responder's default.

<Steps>
  <Step title="Turn on the review responder">
    Run this in the clone. `--machine` takes the machine's hostname or daemon ID. `gate_command` is the check that must pass before anything is pushed; the default runs `gofmt` and your short test tier, so set it for your repository.

    ```bash terminal
    reliant trigger activate --workflow builtin://autopilot-review-responder \
      --machine build-box --project-id 9859294a-8b3c-419f-a5c4-eb85a022fd65 \
      --param 'repos=["reliant-labs/guides-sandbox"]' \
      --param 'gate_command=go test ./...' \
      --name-prefix "guides-sandbox-responder · review-responder"
    ```

    ```text
    TRIGGER           OUTCOME  ACTIVATION
    review-submitted  enabled  guides-sandbox-responder · review-responder · review-submitted (339127e8-...)
    review-comment    enabled  guides-sandbox-responder · review-responder · review-comment (43ac31df-...)
    pr-comment        enabled  guides-sandbox-responder · review-responder · pr-comment (dc42945a-...)
    ```

    The triggers wake it for a review, an inline comment and a pull request comment. In the app: **Workflows → Library → Autopilot · review responder → Set up**. Settings: [Autopilot settings](/guides/autopilot#review-responder).
  </Step>
  <Step title="Opt a pull request in">
    The responder only touches pull requests carrying `agent:authored`, which the [issue worker](/guides/workflows/github-issues-to-pull-requests) puts on the pull requests it opens, or `agent:respond`, which you add to any other:

    ```bash terminal
    gh pr edit 6 --add-label agent:respond
    ```

    A pull request from a fork is never pushed to.
  </Step>
  <Step title="Check whose feedback counts">
    Feedback counts only from you, the accounts in `trusted_ids`, and [Autopilot PR review](/guides/workflows/review-pull-requests-with-ai) when it has findings. To test that, save the `review-submitted` filter from the [workflow source](https://github.com/reliant-labs/reliant/blob/main/internal/workflow/builtin/autopilot-review-responder.yaml) as `filter.cel` and evaluate it against a sample event:

    ```bash terminal
    reliant workflow eval --integration github --event pull_request_review.submitted \
      --scope trigger --kind expression \
      --trigger-payload '{"attributes":{"repository":"acme/app","state":"changes_requested"},"data":{"pull_request":{"number":12,"labels":["agent:respond"]},"review":{"body":"Handle an empty slice in Average."}}}' \
      --trigger-sender '{"kind":"github","id":"583231","verified":true}' \
      --activation-params '{"repos":["acme/app"],"trusted_ids":[],"authored_label":"agent:authored","respond_label":"agent:respond"}' \
      --owner-github-id 583231 - < filter.cel
    ```

    ```text
    trigger.payload: generated from the payload github declares for pull_request_review.submitted, with your trigger_payload merged over it
    true
      type: bool (read as expression)
    ```

    The same event on a pull request labelled only `bug` prints `false`.
  </Step>
  <Step title="Review the pull request">
    Leave a review with a body, or comment on a line:

    ```bash terminal
    gh pr review 6 --comment -b "Add a test for a string shorter than n, so this case stays fixed."
    reliant trigger events 339127e8-2be8-4f2c-b65c-3b41376e596d   # the review-submitted activation
    ```

    The newest row should say `launched` with a chat ID. Follow it with `reliant workflow follow <chat>` or under **Workflows → Runs**.
  </Step>
  <Step title="Read what it did">
    On the pull request, look for:

    - a lease comment and the `agent:working` label while the run holds the pull request;
    - a commit on the pull request's branch, pushed only after `gate_command` passed (a run whose changes fail it twice pushes nothing);
    - a reply in each inline thread, and one summary comment for the round;
    - `agent:working` removed when the round ends.

    Feedback that arrives during a round is picked up by another round. After `max_review_rounds` (3 by default) the pull request is labelled `agent:blocked` and left to you.
  </Step>
  <Step title="Turn it off">
    Pass `--project-id`, or `deactivate` pauses the workflow in every project you own:

    ```bash terminal
    reliant trigger deactivate --workflow builtin://autopilot-review-responder \
      --project-id 9859294a-8b3c-419f-a5c4-eb85a022fd65
    ```
  </Step>
</Steps>

## What this does not do

- **It never approves or merges.** No Autopilot workflow calls a merge. To merge from a workflow you compose that step yourself ([Merging is a workflow step](/integrations/github#merging-is-a-workflow-step-never-an-agent-tool)).
- **It pushes only to the pull request's own branch.** Never to the default or a protected branch, never with `--force`. The agent's shell has no credentials.
- **It ignores strangers.** Feedback from anyone outside `trusted_ids` starts nothing and never reaches the agent.
- **It has no budget of its own.** Each round is up to 80 agent turns, three rounds per pull request, plus a retry. See [What it costs](/guides/autopilot#what-it-costs).

## Troubleshooting

<AccordionGroup>
  <Accordion title="This automation runs only on its organization's AI accounts, and none of them can run the flagship model.">
    `trigger events` shows the firing as `failed` with this detail and no chat: the event passed the filter, but the run could not start. An admin can add an organization API key or turn on Reliant credits, or set `--param 'model={"tags":["fast"]}'` to a model an organization account can run.
  </Accordion>
  <Accordion title="pr-comment failed: deadline exceeded">
    Turning on all three triggers in one call can time out, and then none is enabled. Run the same command once per trigger, adding `--trigger review-submitted`, then `--trigger review-comment`, then `--trigger pr-comment`.
  </Accordion>
  <Accordion title="Nothing fires after a review">
    Check that the pull request carries `agent:authored` or `agent:respond`, that the review has a body (an approval with no text is not feedback), and that it came from you or an account in `trusted_ids`.
  </Accordion>
</AccordionGroup>
