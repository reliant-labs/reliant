Drift is the gap between what an environment should run and what it does run. It has two directions: the platform runs something other than the release you promoted, or your `deploy/kcl/` declares something nobody has deployed yet. Forge answers each with one read-only command, and a third for workloads that something other than forge deploys.

Forge can answer these without logging in to a cluster because every release records the digests it pins and every deploy records the shape it applied ([What gets deployed](/forge/deploy/what-gets-deployed)).

## Before you begin

- A deployed environment. [Deploy a Go API with managed Postgres](/guides/hosting/deploy-go-api-managed-postgres) creates one on Reliant hosting.
- Forge v1.6.1 or later (`reliant forge --version` inside the project).

<Steps>
  <Step title="Check the environment runs its release">
    `env status` compares the images the platform serves with the digests of the release the environment is promoted to:

    ```bash terminal
    reliant forge env status prod
    ```

    ```text
    Verifying environment prod against release v9.9.1 (1 image(s))
      promoted 2026-11-20T16:59:47Z (promote time, NOT deploy time — that gap is what this command checks)
      source   control-plane observer (forge cannot read a hosted env's cluster)

      MATCH        registry.reliantapi.com/<org-id>/shop/shop
      MATCH        registry.reliantapi.com/<org-id>/shop/shop

    2 match, 0 drifted, 0 missing, 0 untagged, 0 unreachable
    ```

    `DRIFTED` means a different image is running than the release pins, and `MISSING` means a pinned image isn't running at all. `UNREACHABLE` with `UserSuspended` is an environment someone [stopped](/guides/hosting/stop-hosted-environment).
  </Step>

  <Step title="Find what your checkout declares but nobody deployed">
    `env diff` renders this checkout and compares it, object by object, with the bundle the last deploy recorded. Here someone added a `worker` workload to `deploy/kcl/prod/main.k` and never deployed it:

    ```bash terminal
    reliant forge env diff prod
    ```

    ```text
    diff of /home/you/shop against live
      (Helm chart objects are not compared; pass --charts to template them)

    prod: ok
      objects: 1 added, 0 removed, 2 changed
        api: config changed
        migrate: config changed
      + workload worker
    ```

    It also reports removed objects, image changes, runtime and cluster moves, secrets newly needed and domain changes. Nothing is built, pushed or contacted. `prod: ok` is the render's status; `error`, `impure` or `stale` means the comparison didn't happen, and is never reported as "no changes". Use `--all` to diff every environment.

    <Note>
      A deploy records each workload's release version in its telemetry attributes, and a render of your checkout doesn't carry one. So right after a release deploy, every workload reads `config changed`. Read the added, removed and image lines, and confirm what runs with `env status`.
    </Note>
  </Step>

  <Step title="Fail a CI job on undeployed changes">
    `env diff` exits `0` whatever it finds, so read its JSON:

    ```bash terminal
    reliant forge env diff prod --json | jq -c '.environments[] | {env, status, added: .diff.workloads_added}'
    ```

    ```text
    {"env":"prod","status":"ok","added":["worker"]}
    ```

    A gate can be `jq -e` over the same document, failing when `status` isn't `ok` or `diff.added` or `diff.removed` is non-empty.
  </Step>

  <Step title="Verify workloads forge doesn't run">
    For a workload on [your own cluster](/guides/hosting/deploy-to-your-own-kubernetes) or under [your own deploy tool](/guides/hosting/keep-helm-fly-cloud-run), `env verify` checks the running image and config per workload:

    ```bash terminal
    reliant forge env verify prod
    ```

    It exits `0` when every workload matches, `1` on drift, and `2` when something couldn't be checked. Hosted workloads are read by `env status`, so on a hosted environment `env verify` reports them `UNVERIFIED` and names `env status`:

    ```text
    WORKLOAD  RUNTIME  IMAGE       CONFIG      RESULT
    migrate   hosted   unverified  unverified  UNVERIFIED
    api       hosted   unverified  unverified  UNVERIFIED

    api:
      image  unverified: forge.OnHosted: the control plane runs it; `forge env status prod` reads it through its observer
    ```
  </Step>
</Steps>

## What this does not do

- **It doesn't fix drift.** All three commands only read. To converge, deploy: `reliant forge env deploy prod` ships the checkout, and naming the version the environment already runs redeploys it. See [Releases and promotion](/forge/deploy/releases-and-promotion).
- **It doesn't watch.** Nothing runs these checks on a schedule or alerts on drift. Run them by hand or from CI.
- **Helm charts aren't compared by default.** Templating them needs `helm` and the network; pass `--charts` to include them.
