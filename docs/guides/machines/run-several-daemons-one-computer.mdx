By the end of this guide you can run more than one Reliant daemon on one computer, for example one per checkout or one for each of two accounts, and check, read or stop any of them from any directory.

Each daemon is an **instance**, named by three things: the server it talks to, the account it runs as, and the workspace it serves. Every combination gets its own folder under `~/.reliant/instances/<server>/<account>/<workspace>/`, with its runtime record, its daemon id and its logs ([one daemon per workspace](/machines/your-computer#one-daemon-per-workspace)). Each instance connects as a separate machine.

## Before you begin

- The `reliant` CLI on the computer ([Installation](/getting-started/installation)).
- One daemon already paired ([connect your computer](/guides/machines/connect-computer-as-machine)). Pairing a new account needs you to approve a code in the app.

<Steps>
  <Step title="See which instance a directory maps to">
    The workspace defaults to the git worktree root of the current directory, so `status` answers for a different instance in each checkout:

    ```bash terminal
    cd ~/src/repo-a/src && reliant daemon status
    cd ~/src/repo-b && reliant daemon status
    ```

    ```text terminal
    No daemon running (no runtime record found)
      Record:   ~/.reliant/instances/https-api.reliantapi.com-c9232e15/_default/repo-a-d194cf53/daemon-state.json
    daemon not running
    No daemon running (no runtime record found)
      Record:   ~/.reliant/instances/https-api.reliantapi.com-c9232e15/_default/repo-b-4622c772/daemon-state.json
    daemon not running
    ```

    The first was run from a subdirectory and still names `repo-a`. `_default` is the account segment before you use more than one account. Outside a git checkout, the workspace is the current directory itself. `status` only looks: it creates nothing, and it exits `1` until a daemon's stream is connected.
  </Step>

  <Step title="Start a daemon for another checkout">
    ```bash terminal
    cd ~/src/repo-b
    reliant daemon start --name repo-b-box
    ```

    The credential in `~/.reliant/daemon.json` belongs to an account, not to a checkout, so the new instance uses it and saves a daemon id of its own. The machine appears in **Settings → Machines** under the `--name` you gave it. Each daemon runs in the foreground: give each one its own terminal, `tmux` window or service unit ([run the daemon on your own server](/guides/machines/run-agents-on-your-own-server)).
  </Step>

  <Step title="Start a daemon for a second account">
    Name the account, by user id, on every command for that daemon. `reliant auth status` shows the account of a `reliant auth login` made by a recent release:

    ```bash terminal
    reliant daemon start --account <user-id>
    ```

    An account with no stored credential pairs first. Approve the code while signed in to the app as that account. With `--token`, the daemon runs as whichever account the pasted token belongs to. Without either, the most recently connected account is used. When you are signed in with `reliant auth login`, `daemon start` passes over another account's stored credential and pairs the computer as you instead. Two accounts can run side by side, even in the same checkout:

    ```text terminal
    Record:   ~/.reliant/instances/https-api.reliantapi.com-c9232e15/usr_alice-188a1a5e/repo-a-d194cf53/daemon-state.json
    ```
  </Step>

  <Step title="List every instance">
    ```bash terminal
    reliant daemon ls
    ```

    Here three daemons have started, none of them signed in yet:

    ```text terminal
    RUNNING  PID     STREAM                UPTIME  INSTANCE
    -        637043  awaiting_credentials  17s     https-api.reliantapi.com-c9232e15/_default/repo-a-d194cf53
    -        637035  awaiting_credentials  17s     https-api.reliantapi.com-c9232e15/_default/repo-b-4622c772
    -        637036  awaiting_credentials  17s     https-api.reliantapi.com-c9232e15/usr_alice-188a1a5e/repo-a-d194cf53
    ```

    **RUNNING** comes from a lock the operating system releases when the process dies, so it can't be stale. A daemon takes that lock once it has a credential and starts serving, so a daemon still signing in shows `-`. A connected one looks like this:

    ```text terminal
    RUNNING  PID    STREAM     UPTIME     INSTANCE
    yes      21208  connected  28h47m57s  https-api.reliantapi.com-c9232e15/_default/workspace-b45e3fc5
    ```
  </Step>

  <Step title="Check, read or stop any instance from anywhere">
    `status`, `logs` and `stop` take the same `--workspace`, `--account` and `--server` as `start`, so you can address any instance from any directory:

    ```bash terminal
    reliant daemon status --workspace ~/src/repo-a --account usr_alice
    reliant daemon logs   --workspace ~/src/repo-b -n 100
    reliant daemon stop   --workspace ~/src/repo-a --account usr_alice
    ```

    ```text terminal
    Stopping daemon (PID 637036)...
    Daemon stopped (PID 637036 exited)
    ```

    `stop` waits for the process to exit and exits `0` once it has. A different `--server` is a different instance too: `--server http://localhost:8080` gives a record under `http-localhost-8080-a76d8c3e/`.
  </Step>

  <Step title="Check that each daemon is connected">
    Run `reliant daemon status` for each instance. It exits `0` only when that daemon's stream is established and stable, and each one shows as a connected machine in **Settings → Machines**.
  </Step>
</Steps>

## What this does not do

- **A workspace isn't a sandbox.** It names the instance. Every daemon runs as your Unix user, and an agent's shell command can reach whatever that user can ([daemon security model](/deep-dives/daemon-security-model)).
- **Accounts that share a Unix user share its files.** Both accounts' credentials are in the same `~/.reliant/daemon.json`, and an agent's shell command under either daemon can read it. Give two people separate Unix users, not separate `--account` daemons.
- **A daemon that is still signing in doesn't block a second start** in the same instance, because it hasn't taken the lock yet. Stop it with `reliant daemon stop` before you start another there.
