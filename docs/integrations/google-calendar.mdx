The Google Calendar integration works as the Google account you connect.

## Connecting

You sign in with Google and approve two permissions: seeing and editing events on your calendars, and seeing the list of calendars you are subscribed to. The connection is labelled with the account's email address. If Google stops accepting the stored sign-in, the connection needs to be reconnected; reconnecting asks for consent again so Google issues a fresh one.

## Actions

| Action | What it does |
|--------|--------------|
| `google_calendar/calendar.list@1` | The calendars on the account's calendar list, with the ids the other actions take and the account's role on each. The primary calendar's id is the account's email address and can also be written `primary` |
| `google_calendar/event.list@1` | Events on a calendar (default `primary`), soonest first. Filter with `time_min` and `time_max` (RFC 3339 with a UTC offset) and `q` (free text). Recurring events are expanded into occurrences unless `single_events` is `false`. Returns each event's id, summary, description, start, end, status, `html_link`, attendees (email and response status), organizer, location and Meet link, up to five pages |
| `google_calendar/event.get@1` | One event by `event_id`, in the same shape |
| `google_calendar/event.create@1` | Create an event from `summary`, `start` and `end` (a timed event takes `date_time` and optionally `time_zone`; an all-day event takes `date`, with the end date being the day after the last day), plus optional `description`, `location` and `attendees`. Set `add_google_meet` to attach a Meet link |
| `google_calendar/event.update@1` | Change an event. Only the fields you pass change. `attendees` replaces the whole guest list |
| `google_calendar/event.delete@1` | Delete an event |

`event.create`, `event.update` and `event.delete` change the calendar, so triggered runs treat them as mutating actions. All three take `send_updates`: `none` (the default), `externalOnly` or `all`. The default means a workflow that creates or cancels an event does not email the guests unless you say so.

When `add_google_meet` is set, Google occasionally fills in the Meet link a moment after the event is created. If `hangout_link` comes back empty, read the event again with `event.get`.

## Not included yet

There is no trigger for new or changed events, and no free/busy lookup. A trigger would poll the calendar, as the [Gmail](/integrations/gmail) one does. Free/busy needs an additional Google permission, so it will arrive with a new consent step. Until then, `event.list` over a time window answers what is on a calendar.

## Example: put a follow-up on the calendar

```yaml
name: book-followup
description: Create a 30-minute follow-up with a Meet link, without emailing the guests
entry: [book]

nodes:
  - id: book
    type: action
    uses: google_calendar/event.create@1
    with:
      summary: "Follow-up with Acme"
      start: { date_time: "2026-12-09T15:00:00", time_zone: "America/New_York" }
      end: { date_time: "2026-12-09T15:30:00", time_zone: "America/New_York" }
      attendees: ["ann@acme.example"]
      add_google_meet: true
```
