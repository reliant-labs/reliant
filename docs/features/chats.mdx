A **chat** is one conversation with an agent or a workflow. It belongs to a **project**, the repository (or several) your agents work in, and it runs on an **agent sandbox**: the computer where the chat's files live and its commands run. You can run many chats at once, in one project or several, and step away while they work.

<Note>
The app calls these computers **agent sandboxes**. Older pages in these docs, the CLI and the `reliant daemon` commands call them **machines**. They are the same thing: [Machines](/machines/overview) is the page for sandboxes.
</Note>

## Find your chats

Open **Agents** in the sidebar. **Chats** lists your conversations under small headings that name the project and the branch or workspace they work in, such as "shopfront · main", and **New chat** starts one. On the new-chat screen you choose the project and the workflow (the default is **Agent**), and you can pick a sandbox or leave it on your [default](/machines/overview#your-default-machine). Anything that needs you, such as an approval or a question from an agent, appears in **Inbox**.

## Projects, branches and workspaces

A chat with no workspace works in the project's main checkout. A **workspace** is an isolated copy of the repo on its own git branch (a git worktree), and a **branched chat** is a chat that works in one. To make one, open the branch menu on any message and choose **Branch to New Chat**, **Branch to New Workspace** or **Branch to Existing Workspace**. The new chat starts with the conversation up to that message, and the original stays untouched. [Branching](/features/branching) covers the menu, and [Workspaces](/features/worktrees) covers creating, archiving and cleaning them up.

Several chats can share one workspace, each with its own history over the same files. A chat on the main checkout can read the Changes tab but not commit from it, so work you want to commit belongs in a workspace.

## Which sandbox a chat runs on

Reliant picks a chat's sandbox once, when its first run starts, and stores the choice with the chat. After that it changes only when you move the chat, or when that sandbox is deleted.

- A **branched chat** always runs on the sandbox that holds its workspace, because the branch exists only on that disk. You can't switch it.
- A chat in the **main checkout** can move to any of your sandboxes that has the project. The move applies from its next run, and no files move with it.
- A **suspended cloud sandbox** wakes when you send a message, so the chat doesn't go to another sandbox that happens to be awake.
- A chat can also run with **no sandbox**. It is offered only tools that don't need your files (web access and [integrations](/integrations/overview)), and it never wakes a sandbox.

[How chats, workspaces and machines fit together](/deep-dives/chats-worktrees-machines) has the full placement rules and what removing a sandbox does.

## When no sandbox is connected

With no usable sandbox, the Chats area shows a prompt to connect one, with two options:

- **Use your own machine.** Run `reliant daemon start`, approve the pairing code in the app, and the computer shows up as a sandbox. The repository stays on that computer. See [Your own computer](/machines/your-computer).
- **Provision a Reliant sandbox.** A cloud computer that sleeps when idle and wakes when a run needs it, billed through a compute plan. See [Cloud machines & plans](/machines/cloud).

Chats still work without a sandbox, in the no-machine form above. Nothing in the project's files is reachable until one is connected.
