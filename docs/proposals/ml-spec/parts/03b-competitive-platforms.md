**Install path**: competitors either own the cluster (CoreWeave, HyperPod, Modal) or require their

## Derived metrics

- Allocation efficiency = Σ GPU util (or SM active) / Σ allocated GPUs, per project.
- Idle GPU-hours = Σ over allocated GPUs of time with util < 5% for ≥ N min; idle $ = × rate.
- Healthy node % = nodes without fault labels/taints / total GPU nodes (HyperPod's KPI).
- Training uptime % = running time / (running + recovery time) (HyperPod training dashboard).
- Goodput = productive step time / allocated time (Google ML Goodput).
- Mean time to remediate = fault detected → node back / job resumed.

## Gotchas

- Run:ai "utilisation" in older versions is `DCGM_FI_DEV_GPU_UTIL` (busy-kernel time), which overstates real use; prefer `DCGM_FI_PROF_SM_ACTIVE`.
- Fractional/time-sliced GPUs: per-pod GPU util cannot be attributed from DCGM, only per device; MIG gets per-instance metrics.
- The HyperPod `GPUXidError` rule fires on `DCGM_FI_DEV_XID_ERRORS > 0`, which is a last-value gauge: it holds the last XID, so the rule keeps firing until the exporter resets.
- Datadog cost scales with per-GPU tag cardinality; customers drop the profiling fields to save money.
- Counters vs gauges: ECC aggregate counts are counters (alert on increase); violation fields are cumulative µs.
