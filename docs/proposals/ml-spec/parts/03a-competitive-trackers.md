## 18. MLflow REST entities we will import (field names)

(Entity list (V) from REST ref 3.18.0; fields (K) per mlflow `service.proto`.)

- **Experiment**: `experiment_id`, `name`, `artifact_location`, `lifecycle_stage` (active/deleted), `last_update_time`, `creation_time`, `tags[]{key,value}`.
- **Run**: `info: RunInfo`, `data: RunData`, `inputs: RunInputs`, `outputs: RunOutputs`.
- **RunInfo**: `run_id`, `run_uuid`(deprecated), `run_name`, `experiment_id`, `user_id`, `status` (RUNNING, SCHEDULED, FINISHED, FAILED, KILLED), `start_time`, `end_time` (ms epoch), `artifact_uri`, `lifecycle_stage`.
- **RunData**: `metrics[]{key, value, timestamp, step, dataset_name?, dataset_digest?, model_id?, run_id?}` (latest value per key; history via `GetMetricHistory` → `metrics[]` + `next_page_token`; `GetMetricHistoryBulkInterval` for sampled), `params[]{key,value}` (immutable, ≤ 6000 chars), `tags[]{key,value}` (system tags `mlflow.parentRunId`, `mlflow.runName`, `mlflow.user`, `mlflow.source.name|type|git.commit|git.repoURL|git.branch`, `mlflow.log-model.history`, `mlflow.note.content`).
- **RunInputs**: `dataset_inputs[]{tags[]{key,value} (`mlflow.data.context`=training/validation/eval), dataset{name, digest, source_type, source, schema, profile}}`, `model_inputs[]{model_id}`. **RunOutputs**: `model_outputs[]{model_id, step}`.
- **LoggedModel**: `info{model_id, experiment_id, name, creation_timestamp_ms, last_updated_timestamp_ms, artifact_uri, status (PENDING/READY/FAILED), creator_id, model_type, source_run_id, status_message, tags, registrations[]}`, `data{params[], metrics[] (with dataset_name/digest)}`.
- **RegisteredModel / ModelVersion**: see §10.
- **Trace (v3)**: `TraceInfo{trace_id, client_request_id, trace_location, request_preview, response_preview, request_time, execution_duration, state (OK/ERROR/IN_PROGRESS), trace_metadata, assessments[], tags}`; spans are OTLP.
- **Assessment**: `assessment_id, assessment_name, trace_id, span_id, source{source_type HUMAN/LLM_JUDGE/CODE, source_id}, create_time, last_update_time, feedback{value, error} | expectation{value}, rationale, metadata, overrides, valid`.
- Batch import: `LogBatch` limits 1000 metrics, 100 params, 100 tags per request (K); SearchRuns paginates `max_results` ≤ 50000 (K).

## 19. Synthesis — the bar we must match, per view

- **Run list**: filter by any config/summary/tag/state with expressions; group-by config key with aggregate rows; sortable/pinnable columns; saved views; bulk tag/archive; state colors incl. crashed vs failed vs killed vs preempted.
- **Run overview**: git commit + dirty diff, command/args, image, packages, host/GPU type/count, config tree (searchable), summary (last/min/max), inputs/outputs (datasets, checkpoints, model), notes, parent/child.
- **Charts**: x = step / wall / relative / any metric; EMA+Gaussian+running-avg smoothing with "show original"; log axes; outlier-ignore scaling; group-by with mean/median + min-max/stddev shading; full-fidelity min/max envelope (no lost spikes) at 1M+ points (Neptune bar); synced zoom; prefix-sections; legend templates; regex metric pickers; custom expressions; forked/resumed lineage stitched as one curve.
- **Compare**: diff-only config table, parallel coordinates with brushing, param importance, scatter, overlays synchronized by step.
- **System**: at least W&B's per-GPU set (util, mem %, mem bytes, temp, power W/%, clocks, ECC) + CPU/RAM/disk/net, per process & per node, at ≤15s.
- **Logs**: per rank/pod/container filter, level filter, search, follow, download (Determined bar).
- **Checkpoints/artifacts**: versioned, digest, aliases, size, metric-at-checkpoint, GC policy, "used by", lineage DAG.
- **Registry**: aliases (unique, protected), model card, lineage back to run+dataset, automations on alias/version events (webhook), RBAC.
- **Evals**: dataset × model × scorer matrix, per-row drill to trace, diff vs base with regression counts, human annotation queues, online scorers with sampling.
- **Traces**: span tree, tokens, cost, latency, TTFT, sessions, add-to-dataset, OTLP ingest.
- **Profiling**: step-time breakdown, kernel table, trace viewer, memory timeline.
- **HPO**: sweep view and early stopping status; **Cluster**: queues + workers + slots (ClearML/Determined).

## 20. Where they are weak

- **Cluster/hardware context**: NVML polling only; no DCGM profiling counters, XID, NVLink/PCIe, throttle/clock-event reasons, node-problem-detector conditions, no node identity across runs ("is this node bad for everyone?").
- **Kubernetes events**: no pod scheduling, image pull, OOMKilled, eviction, Kueue admission/wait, JobSet restarts in the run timeline.
- **Restarts/preemptions**: resumed runs show a gap (W&B) or nothing; only Determined counts restarts. No attempt-level attribution of lost steps/goodput.
- **Cost**: GPU-hours × price per run/experiment/team absent in trackers (Braintrust/LangSmith only LLM token cost).
- **Release/serving lineage**: registry ends at "alias = production"; no image digest, deploy, canary health, prod traffic, rollback history.
- **Code-level traces**: LLM spans only; no join to service traces, data-loader code, continuous profiles, or the inference engine (vLLM scheduler, KV cache) behind a span.
- **Alerting**: no hang/straggler/NCCL detection; alerts are user-coded `run.alert`.
- **Neptune's exit** leaves teams with 100k-step/large-scale chart expectations underserved; MLflow's UI is weak at scale.

## 21. What Reliant's integrated angle wins

- **Run timeline = metrics + k8s events + node/GPU health + logs + restarts in one view**, with phase/attempt as first-class (Determined-grade restarts, better: per-attempt cause — XID 79 on node X, preemption by Kueue, OOMKilled).
- **Release ledger**: checkpoint → model version → image digest → env promotion → `forge obs check` verdict; registry alias changes become releases with health proof and roll-forward.
- **Changes A/B**: serve two model versions behind a flag; the experiment readout joins online eval scores, latency and cost — the eval → prod loop none of the trackers close.
- **Code-joined traces + runtime context**: LLM/inference span → vLLM engine metrics → pod → GPU → node; training step span → data loader profile → continuous profile.
- **Cost**: GPU-seconds by run/phase/attempt/team from cluster truth, incl. wasted (failed attempts, idle allocation).
- **Agents**: detect `dcgm-profiling-off`-style gaps and draft the KCL to install the missing exporter; on a regression or bad node, open a PR (taint/cordon, config fix, rollback) — not just an alert.
- **Import, don't replace**: ingest MLflow (§18) / W&B runs so users keep their SDK; we add the cluster and release context they lack.
