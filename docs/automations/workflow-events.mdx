---
title: "Workflow events"
description: "Start a run when another of your workflows finishes, fails or blocks"
---

A workflow-event automation chains workflows without wiring them together. It fires when a run of one of *your* workflows reaches an outcome, which makes it the natural place for "if the nightly job fails, do something about it".

```yaml
name: failure-follow-up
description: Open a follow-up when a Get It Right run fails
entry: [follow_up]

triggers:
  - name: run-failed
    workflow_event:
      workflows: [builtin://get-it-right]
      outcomes: [failed]

nodes:
  - id: follow_up
    type: workflow
    ref: builtin://agent
```

| Field | Meaning |
|-------|---------|
| `workflows` | Which workflows' runs to watch, as a slug or `builtin://<name>`. Empty means any of your workflows |
| `outcomes` | `finished`, `failed` or `blocked` (waiting on an approval or a question). Empty means all three |

A workflow-event trigger never fires on a run that it started itself, or on that run's descendants, so two workflows cannot trigger each other forever, and a chain of event-launched runs stops at five hops. If a name in `workflows` does not resolve yet, validation warns that the trigger matches nothing until the workflow exists.

## What the run sees

`trigger.payload` describes the run that reached the outcome. Every key is always present, empty when it does not apply:

| Key | Holds |
|-----|-------|
| `run_id` (also `chat_id`) | The run that reached the outcome; open it in **Workflows → Runs** |
| `workflow_name`, `workflow` | Its workflow, by name and as the reference `workflows` compares against |
| `project_id`, `chat_title` | Where it ran, and its title |
| `outcome` | `finished`, `failed` or `blocked` |
| `summary` | The run's final summary, for `finished` |
| `error` | Why it failed, for `failed` |
| `blocked_on`, `prompt` | For `blocked`: `approval` or `question`, and what it asks |

Use `filter` to narrow further, in the same way as for any other kind (`filter: "trigger.payload.error.contains('timeout')"`), and see [Automations](/automations/overview) for the shared fields.
