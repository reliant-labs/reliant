## Common Node Fields

These fields are available on **all** node types. They provide shared functionality for node identification, conditional execution, machine placement, and output handling. Everything else a node takes is specific to its type, listed in its section below.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | string | Yes | Unique within the workflow; other nodes read this node's outputs as nodes.`<id>`.* |
| `type` | string | Yes | The node type, such as workflow, call_llm, run or loop; each section below names its own |
| `condition` | string | No | Raw CEL (no \{`{ }`\}): the node runs only when it is true, and is skipped otherwise. On a join node, all or any |
| `timeout` | string | No | Overrides the node's default timeout, as a duration such as 30s, 5m or 1h30m |
| `save_message` | SaveMessageConfig | No | A message to save to the thread when the node completes, as a template over output.* |
| `daemon` | CelDaemonSelector | No | Which machine runs this node's tools, overriding the workflow's daemon setting |
| `outcome` | string | No | The verdict reaching this node stamps on the run: success or failure. The last node that runs with one decides the run's outcome (enum: success\|failure) |

### Thread Configuration

Workflow, loop and router nodes take a `thread` field that controls conversation context:

```yaml
- id: analyze
  type: workflow
  ref: builtin://agent
  thread:
    mode: fork      # fork, new, or inherit (default)
    memo: true      # reuse across loop iterations
    inject:
      role: user
      content: "Analyze: {{inputs.data}}"
```

### Conditional Execution

Use `condition` to skip nodes based on runtime state:

```yaml
- id: cleanup
  type: run
  condition: "nodes.process.exit_code != 0"
  command: "rm -rf temp/"
```

### Automatic Message Saving

Use `save_message` to capture output without a separate save_message node:

```yaml
- id: summarize
  type: workflow
  ref: builtin://agent
  thread:
    mode: fork
  save_message:
    role: assistant
    content: "{{output.response_text}}"
```

## Compute

`type: compute`

Compute named values from CEL expressions: no model, no shell, no worker round trip. Each output is \{`{ expr }`\} (or a literal); a value that is exactly one \{`{ }`\} keeps its type. Read them as nodes.`<id>`.`<name>`. Outputs cannot read each other: chain two compute nodes when one feeds the next. A failing expression fails the node. Use it for deterministic logic (labels, sizes, expiry, parsing a node's JSON stdout) instead of a script

### Inputs

|-------|------|----------|---------|-------------|
| `outputs` | map | No | - | Named values, each a \{`{ }`\} expression (or a literal). Read them as nodes.`<id>`.`<name>` |
