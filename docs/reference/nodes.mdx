## Common Node Fields

These fields are available on **all** node types. They provide shared functionality for node identification, conditional execution, machine placement, and output handling. Everything else a node takes is specific to its type, listed in its section below.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | string | Yes | Unique within the workflow; other nodes read this node's outputs as nodes.`<id>`.* |
| `type` | string | Yes | The node type, such as workflow, call_llm, run or loop; each section below names its own |
| `condition` | string | No | Raw CEL (no \{`{ }`\}): the node runs only when it is true, and is skipped otherwise. On a join node, all or any |
| `timeout` | string | No | Overrides the node's default timeout, as a duration such as 30s, 5m or 1h30m |
| `save_message` | SaveMessageConfig | No | A message to save to the thread when the node completes, as a template over output.* |
| `daemon` | CelDaemonSelector | No | Which machine runs this node's tools, overriding the workflow's daemon setting |
| `outcome` | string | No | The verdict reaching this node stamps on the run: success, failure, or skipped (it chose not to do its work this time, for an expected reason that clears on its own; not a failure). The last node that runs with one decides the run's outcome (enum: success\|failure\|skipped) |
| `tolerate_failure` | boolean | No | Make the node optional: when it fails the run continues, and nodes.`<id>`.failed is true with the reason in nodes.`<id>`.error |
| `observe` | NodeObserve | No | What the node records when it finishes: span attributes, events (a decision is an event named decision) and metrics, as templates over output.*. Never fails the node |
| `role` | string | No | The engine role this node acts in. Only reviewer, and only on a review node, which requires it (enum: reviewer) |
| `preflight` | NodePreflight | No | Check the machine before the node's work starts (disk, /tmp, uid, tools, load); a machine that fails is never given the node, which moves to another member of its pool without spending an attempt. true, or a mapping of overrides |

### Thread Configuration

Workflow, loop and router nodes take a `thread` field that controls conversation context:

```yaml
- id: analyze
  type: workflow
  ref: builtin://agent
  thread:
    mode: fork      # fork, new, or inherit (default)
    memo: true      # reuse across loop iterations
    inject:
      role: user
      content: "Analyze: {{inputs.data}}"
```

### Conditional Execution

Use `condition` to skip nodes based on runtime state:

```yaml
- id: cleanup
  type: run
  condition: "nodes.process.exit_code != 0"
  command: "rm -rf temp/"
```

### Automatic Message Saving

Use `save_message` to capture output without a separate save_message node:

```yaml
- id: summarize
  type: workflow
  ref: builtin://agent
  thread:
    mode: fork
  save_message:
    role: assistant
    content: "{{output.response_text}}"
```

### Observability (`observe`)

Any node can declare what it records when it finishes: attributes on its span, span events, and metrics, each a template over the node's own result. A workflow-level `observe:` is the default for every node of that graph: attributes merge by key and metrics by name (the node wins), and events are concatenated, defaults first.

```yaml
- id: plan
  type: compute
  outputs:
    cut: "{{ inputs.ready }}"
    hold: "{{ inputs.ready ? '' : 'not_ready' }}"   # why it did not cut, as a code
  observe:
    attributes:
      attempt: "{{ node.attempt }}"
    events:
      - name: decision         # the recommended convention: name, value, reason
        attributes:
          name: cut
          value: "{{ output.cut ? 'cut' : 'no_cut' }}"
          reason: "{{ output.hold }}"
    metrics:
      - name: rc_train.ticks
        kind: counter          # counter, histogram or gauge
        attributes: { decision: "{{ output.cut ? 'cut' : 'no_cut' }}" }
```

An expression sees `output` (this node's result), `inputs`, `trigger`, `workflow`, `iter` and `node` (`id`, `type`, `path`, `attempt`, `duration_ms`); not `nodes`, so a value computed from other nodes becomes one of this node's outputs first. An event's optional `when:` (raw CEL) gates it, and `each:` emits one event per element of a list, bound to `item`. A metric's `value` is optional for a counter and required for a histogram or gauge. Names and keys are lower-case and dotted (`rc_train.ticks`). Recording never fails, retries or delays the node, and validation only warns about an `observe` expression; `reliant workflow lint` reports it as an error (`observe-invalid`).

A node that runs as an activity (`call_llm`, `execute_tools`, `run`, `action`, `invoke_tool` and the rest) is recorded when it succeeds: its attributes and events are stored with the run and set on the node's span, and its metrics are emitted as `reliant.observed.<name>`. A node the workflow completes itself (`compute`, `join`, `router`, `loop`, `workflow`) is not recorded yet. Telemetry carries a string only when it is one code-like token (`no_cut`, `review:changes`); any other string is withheld from it and kept only in the stored record, and a metric attribute that is not a bool, an integer or such a code is recorded as `other`.

A server that predates `observe` refuses a file that uses it, so add `observe` to a workflow only once every server and CLI that reads the file runs a release that reads it.

## Compute
