A forge project describes every place it runs as code. Each **environment** is a directory under `deploy/kcl/`, and a new project has three: `dev` runs on your machine, while `staging` and `prod` deploy to [Reliant hosting](/forge/hosting). Deploying is the same command for every environment and every target, so once you know how releases and plans work you know how to ship anywhere.

## The shortest path

```bash
forge env deploy staging                       # build this checkout, cut a release, show the plan, deploy it
forge env deploy prod --from staging           # ship exactly what staging runs
forge env status prod                          # the release prod is bound to, and whether it is healthy
```

Nothing is written until you approve a plan, a deploy waits for health before it reports success, and the exit codes tell a script whether to retry, stop, or hand a link to a person. [Releases and promotion](/forge/deploy/releases-and-promotion) has all of it.
