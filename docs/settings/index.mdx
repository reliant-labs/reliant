Reliant separates user-editable configuration from internal application data.

## User configuration locations

| Location | Purpose | Typical git status |
| --- | --- | --- |
| `~/.reliant/config.yaml` | Global config: models, provider preferences, shared settings | Not in git |
| `~/.reliant/mcp.json` | Global MCP servers | Not in git |
| `~/.reliant/reliant.md` | Global context for all projects | Not in git |
| `.reliant/config.yaml` | Project config | Usually committed |
| `.reliant.local/config.yaml` | Local project overrides | Usually ignored |
| `reliant.md` | Shared project memory | Usually committed |
| `reliant.local.md` | Personal local context | Usually ignored |

## Internal data

Reliant stores app data, databases, and logs in platform-appropriate application directories. These are distinct from your editable configuration files.

## Why the split matters

Global settings keep core model/provider behavior consistent across projects, while project settings let teams version workflows, presets, and shared context as code.
